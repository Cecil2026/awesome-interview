### 1. 偏差-方差权衡

**频率：** 高

**题目：** 请解释偏差-方差权衡。如何诊断一个模型是受偏差限制还是受方差限制？

**答案：** 泛化误差可分解为三部分：**偏差**（错误建模假设带来的误差——模型太简单，抓不住信号，即欠拟合）、**方差**（对具体训练样本的敏感性——换一批数据拟合结果就大幅波动，即过拟合），以及**不可约噪声**（标签本身固有的随机性，永远无法消除）。粗略地说，期望测试误差 ≈ 偏差² + 方差 + 噪声。

直观例子：用直线去拟合明显弯曲的数据是**高偏差**——无论加多少数据都抓不住规律；在几百行数据上生长一棵不剪枝的决策树是**高方差**——它记住了噪声，样本一变结果就剧烈摇摆。

**诊断**是关键的实操技能：对比训练误差与验证误差。差距大（训练低、验证高）说明是方差/过拟合；两者都高且接近说明是偏差/欠拟合；两者都低说明状态良好。

**对症的手段各不相同。** 降方差：加数据、加正则化（L1/L2、dropout、early stopping）或用 bagging 集成。降偏差：加容量（更深/更宽的模型）、加特征或用 boosting 集成。用错手段（比如对已经欠拟合的模型再加正则化）只会更糟，所以必须先诊断。

经典的 U 型曲线（误差先降后升）在现代过参数化网络中被 **double descent** 复杂化了——一旦越过插值阈值继续增大容量，测试误差会*再次*下降。即便如此，偏差-方差框架仍是决定下一步该改什么的日常工具。

**要点：**
- 训练/验证差距用于诊断偏差与方差。
- 正则化与更多数据降低方差。
- 增加容量或特征降低偏差。
- 过参数化场景下出现 double descent。

### 2. 过拟合及其防止方法

**频率：** 高

**题目：** 什么是过拟合？如何防止它？

**答案：** 过拟合是指模型捕获了**训练噪声**而非潜在规律——它把训练误差压得很低，却泛化很差，测试误差居高不下。典型信号是训练-验证曲线发散：训练损失持续下降，而验证损失先走平后回升。

**常见成因：** 模型容量相对数据量过大、特征过多（高维低样本）、训练时间过长、验证设置有泄漏让模型偷看答案，或类别不平衡让它走捷径。

**缓解手段，由易到繁：**
- *更多、更干净的数据*——最有效的单一手段；数据稀缺时用数据增强（裁剪、翻转、加噪、改写）来合成。
- *降低有效容量*——更简单的模型、更少的特征，或用 L1/L2 权重衰减惩罚大权重。
- *深度学习正则化器*——dropout、early stopping、batch/layer norm、label smoothing 是第一道防线。
- *诚实估计*——交叉验证和一个保留的测试集，让你度量真实泛化。
- *集成*——平均多个模型可抵消各自的独立误差。

深度学习中以数据增强和 dropout 为主；经典/表格 ML 中以正则化和特征选择为主。最重要的是，在最终评估前保持**测试集绝不触碰**——在测试集上调参会悄悄泄漏信息，给出一个过于乐观、到生产就崩塌的数字。

**要点：**
- 训练低、验证高 = 过拟合。
- 正则化、dropout、early stopping 是核心工具。
- 更多/更干净的数据胜过精巧技巧。
- 永远不要在测试集上调参。

### 3. 训练/验证/测试集划分与交叉验证

**频率：** 高

**题目：** 如何将数据划分为训练/验证/测试集？何时改用交叉验证？

**答案：** 三种划分各司其职：**训练集**拟合模型参数，**验证集**调超参数和选模型，**测试集**给出一次性、最终、无偏的泛化估计。大数据集的典型比例是 70/15/15 或 80/10/10。

数据**稀缺**时，固定 holdout 会浪费太多数据且估计噪声大。改用 **k 折交叉验证**（k=5 或 10）：轮流让每一折当验证集，使每个样本都既参与训练又参与验证，再对 k 个分数取平均得到更稳定的估计。代价是训练时间变为 k 倍。

**划分策略必须匹配数据结构，否则会泄漏：**
- *分类*——按标签**分层**，让每个划分都保持类别比例（对不平衡或小数据集至关重要）。
- *时间序列*——用**前向链式**（滚动窗口）划分，始终用过去训练、预测未来；随机打乱会让模型"看到未来"从而虚高。
- *分组数据*（同一用户/会话多行）——**按组**划分，让一个用户的所有行落在同一侧；否则近似重复行会从训练泄漏到测试。

铁律：测试集只在最后**触碰一次**。你对它做的每个决策都会悄悄泄漏信息；若发现自己在根据测试结果迭代，就另切一个全新的保留集做最终检验。

**要点：**
- 测试集只在最后用一次。
- 分类要分层，时间序列要按时序。
- 分组划分防止用户级泄漏。
- 小数据用 k 折，大数据用 holdout。

### 4. 正则化：L1 vs L2 vs 弹性网

**频率：** 高

**题目：** 请对比 L1、L2 和弹性网正则化。各自何时选用？

**答案：** 三者都在损失中对权重大小加惩罚以抑制过拟合，但对权重的塑形方式不同。

**L2（岭回归）** 加 `lambda * sum(w^2)`。其梯度将权重平滑、成比例地收缩至接近零，但很少精确*到*零，因此保留所有特征、赋予小而稳定的系数。它优雅地处理多重共线性，且有干净的闭式解。当大多数特征都携带一些信息、你想要稳定预测时选它（稠密信号）。

**L1（lasso）** 加 `lambda * sum(|w|)`。其恒定大小的梯度把许多权重精确推**到零**，实现隐式特征选择，产生稀疏、可解释的模型。缺点：在一组相关特征中，它会任意保留一个、把其余归零，可能不稳定。当你想要紧凑模型或想识别哪些特征重要时选它。

**弹性网** 结合两者：`lambda * (alpha * L1 + (1 - alpha) * L2)`。兼具 L1 的稀疏性和 L2 的稳定性，且关键在于能**整组选择**相关特征而非任意挑一个。当特征相关但你仍想要稀疏性时选它——常见于基因组学等宽数据集。

神经网络中 L2 是标配，称为**权重衰减**。一个细节：使用自适应优化器时，把 L2 加进损失会与逐参数学习率缩放产生糟糕的相互作用。**AdamW** 通过*解耦*权重衰减修复了这点——直接作用于权重而非通过梯度——这正是 AdamW 成为现代默认的原因。用交叉验证调 `lambda`（和 `alpha`）。

**要点：**
- L1 = 稀疏；L2 = 收缩；弹性网 = 两者兼具。
- L1 在相关特征间任意选择。
- AdamW 将权重衰减与自适应步长解耦。
- Lambda 通过交叉验证调优。

### 5. 特征工程与特征选择

**频率：** 高

**题目：** 请谈谈特征工程与特征选择。为什么数据泄漏是最关键的风险？

**答案：** **特征工程**从原始数据创造预测信号。常见手段：类别编码（低基数用 one-hot，高基数用 target/均值编码或学习嵌入）、数值缩放（标准化或 min-max）、连续值分箱、构造交互项和多项式项、对偏态变量做对数/Box-Cox 变换、日期分解（星期几、是否节假日）以及领域聚合（如用户 30 天平均消费）。

**特征选择**剪除冗余或噪声输入以减少过拟合并提速。三大类：
- *Filter* 方法独立地为每个特征打分（相关性、互信息、卡方）——快但忽略交互。
- *Wrapper* 方法通过反复重训搜索子集（前向/后向选择、RFE）——准但昂贵。
- *Embedded* 方法在训练中顺带完成选择（L1 正则化、树特征重要性）——实用的折中。

现代深度学习把大量此类工作交给**表示学习**，但表格问题仍取决于特征质量的成败。

**泄漏是隐形杀手。** 任何使用目标统计量的变换——target encoding、均值填充、缩放参数，甚至 TF-IDF 的词表——都必须*仅在训练折上拟合*，再应用到验证/测试。在全集上拟合会让关于答案的信息渗入特征，产生惊艳的离线分数却在生产中崩塌。安全做法是把每个此类变换包进管道，在每个交叉验证折内重新拟合。

**要点：**
- 表格机器学习的成败在特征。
- 泄漏是隐形杀手；变换只在训练集上拟合。
- 嵌入替代高基数类别的 one-hot。
- L1 与树重要性是实用的 embedded 选择器。

### 6. 类别不平衡的处理

**频率：** 高

**题目：** 如何处理分类问题中的类别不平衡？

**答案：** 当一个类占绝大多数时——欺诈占 0.1%、疾病占 1%——总预测多数类的模型能拿到 99%+ 准确率，却一个正例都抓不到。所以第一步是**停用准确率**，选择能反映少数类的指标：PR-AUC、F1、recall@k 或显式成本加权指标。

**补救手段，大致按优先度：**
- *类别权重*——让损失更重地惩罚少数类错误（sklearn 的 `class_weight='balanced'`、PyTorch 的 `pos_weight`）。便宜、安全、不动数据，通常先试这个。
- *阈值调优*——默认 0.5 截断是任意的；沿精确率-召回率曲线移动它以达到目标召回或精确。常是单一最大、最简单的收益。
- *重采样*——过采样少数类（SMOTE/ADASYN 合成插值点）、欠采样多数类或两者结合。有效但风险更大。
- *Focal loss*——降低易样本权重，让训练聚焦难的少数类；常用于目标检测。

**常见陷阱：**
- SMOTE 在高维会在相隔很远的邻居间生成不真实的合成点。
- **划分前过采样会泄漏**——测试点的合成副本会进入训练。始终在划分后、每个 CV 折*内*重采样。

极端不平衡（十万分之一）时，纯重平衡很吃力；**异常检测**建模或**两阶段**流水线（高召回的廉价过滤器 + 精确分类器）通常更优。

**要点：**
- 不平衡下准确率会撒谎；用 PR-AUC、F1、recall@k。
- 类别权重比合成过采样更省更稳。
- 调阈值常是最简单的大收益。
- SMOTE 应在 CV 折内做，不能在划分前。

### 7. 分类指标：精确率、召回率、F1、ROC-AUC、PR-AUC

**频率：** 高

**题目：** 请定义精确率、召回率、F1、ROC-AUC 和 PR-AUC。如何选择优化哪个？

**答案：** 从混淆矩阵（TP、FP、FN、TN）出发：
- **精确率** = TP/(TP+FP)：你标为正的东西中有多少是对的。避免误报时升高。
- **召回率**（敏感度）= TP/(TP+FN)：所有实际正例中你抓住了多少。避免漏报时升高。
- **F1** = 精确率与召回率的调和平均——一个惩罚"牺牲一方换另一方"的单一数字。

精确率与召回率**通过决策阈值权衡**：降低阈值能抓住更多正例（召回升）但伴随更多误报（精确降），反之亦然。因此单一工作点很少能说明全貌。

**与阈值无关的汇总指标：**
- **ROC-AUC** 绘制所有阈值下的真阳性率 vs 假阳性率；它度量排序质量且对类别平衡不敏感——但这种不敏感使它在严重不平衡下*乐观地偏高*，因为庞大的真阴性数量压低了 FPR。
- **PR-AUC** 绘制精确率 vs 召回率，正例稀少时更具信息量，因为它完全忽略真阴性。

**选指标取决于错误的成本：**癌症筛查优先召回（漏报致命，误报不过多做一次检查）；垃圾邮件过滤优先精确（误标真邮件比放过垃圾更糟）；排序/推荐用 AUC 或 NDCG。务必报告**多个**指标加混淆矩阵，并按真实运营约束调阈值而非默认 0.5。

**要点：**
- 精确率与召回率通过阈值权衡。
- 严重不平衡下 PR-AUC > ROC-AUC。
- 仅看准确率几乎从不够。
- 混淆矩阵显示真实错误构成。

### 8. 数据泄漏

**频率：** 高

**题目：** 什么是数据泄漏？它有哪些形式，如何预防？

**答案：** 泄漏是指模型在预测时本不应拥有的信息悄悄进入了训练。它产生看上去很棒的验证分数，却在生产中崩塌——是最昂贵的一类 ML bug，因为它一直隐藏到部署才暴露。

**常见形式：**
- *目标泄漏*——特征源自或代理了标签。经典例：欺诈模型中的 `was_refunded`，或预测诊断时包含 `diagnosis_date` 字段。
- *训练-测试污染*——划分前在全集上拟合预处理（scaler、编码器、填充器、PCA），使测试统计量泄入训练特征。
- *时间泄漏*——用未来信息预测过去，或对时序数据随机划分。
- *组泄漏*——同一用户/患者/设备同时出现在训练和测试中，模型记住实体而非规律。
- *重复行*跨越划分。

**症状：** 验证"好得不真实"、单个特征主导重要性，或离线与线上性能差距很大。

**预防：** *先*划分，再将每个变换仅在训练折上拟合（包进管道按折重拟）；时序数据用**时间感知**划分、分组数据用**组感知**划分；并批判性地阅读 top 特征——若某个几乎完美预测，就怀疑它编码了答案。每当离线大幅胜过线上时，先假定有泄漏。

**要点：**
- 先划分，后变换。
- 可疑的 top 特征往往 = 泄漏。
- 时间/组感知划分防止隐性泄漏。
- 离线-线上差距是经典症状。

### 9. 逻辑回归

**频率：** 高

**题目：** 逻辑回归如何工作？为什么它仍是强大的生产基线？

**答案：** 尽管名为回归，它其实是**分类器**。它计算线性得分 `z = w·x + b`，再用 **sigmoid** `1/(1+e^-z)` 压缩成 0 到 1 之间的概率（多分类用 **softmax** 推广）。当概率越过阈值时预测正类。

**拟合：** 最大化标签的对数似然，等价于最小化**交叉熵**损失。这个目标是**凸**的，所以梯度下降能到达唯一全局最优——无需随机重启，无局部最小。无闭式解（区别于线性回归），但收敛可靠。

**为何在生产中备受青睐：**
- *校准的概率*——输出是有意义的似然而非仅仅得分，对排序、阈值化和期望值决策至关重要。
- *可解释性*——每个系数都是对数几率效应：取指数得到可向监管或产品方解释的几率比。
- *可扩展到巨大稀疏特征空间*——百万维的文本和广告点击特征训练很快。
- 用 L1（稀疏）、L2（收缩）或弹性网正则化。

**局限：** 决策边界在特征空间中是**线性**的（加交互/多项式特征或核来捕捉曲率），对离群值和多重共线性敏感，并假设观测大致独立。即便如此，对于点击预测、信用评分，以及任何校准、可解释概率胜过几点原始准确率的场景，它仍是每个严肃模型都要对标的默认基线。

**要点：**
- 凸、校准好、可解释。
- 高维稀疏问题的强基线。
- 加交互或核函数突破线性上限。
- 正则化处理共线与过拟合。

### 10. 决策树

**频率：** 高

**题目：** 请介绍决策树：(1) 它如何通过贪心划分递归分割特征空间（分类用信息增益/基尼不纯度、回归用方差最小化）以及能处理混合类型、缺失值、非线性而无需缩放的特点，(2) 它的主要弱点（高方差、易过拟合）和用 max_depth、min_samples_leaf、ccp_alpha 剪枝的控制手段，以及 (3) 为什么单独的树很少出彩却是随机森林与梯度提升树的基石、贪心划分可能错过特征交互而集成能修复。

**答案：** 通过贪心划分递归分割特征空间，分类时最大化信息增益（熵减）或基尼不纯度下降，回归时最小化方差。处理混合类型、缺失值和非线性而无需缩放。浅树易解释。主要弱点：高方差——小数据变化可能产生很不同的树——以及过拟合倾向。用 max_depth、min_samples_leaf、ccp_alpha 剪枝控制。单独的树很少出彩，但它是最强表格方法的基石：随机森林（bagging）和梯度提升树（XGBoost/LightGBM/CatBoost）。贪心划分可能错过特征交互；集成可修复。

**要点：**
- 基于不纯度的贪心划分；无需缩放。
- 单独高方差；需集成才强。
- max_depth 与 min_samples_leaf 控制过拟合。
- 是 RF 与梯度提升的基础。

### 11. 随机森林

**频率：** 高

**题目：** 随机森林如何工作？为什么它几乎无需调优就表现良好？

**答案：** 随机森林是通过 **bagging**（bootstrap 聚合）组合的决策树集成，额外加一个小机制。每棵树在**bootstrap 样本**（有放回抽取 n 行）上训练，且每次划分只能考虑**随机特征子集**（分类常用 √p，回归用 p/3）。预测取平均（回归）或多数投票（分类）。

关键洞察是**去相关**。单纯 bagging 会留下相关的树，因为少数强特征主导了每棵树的顶部划分。限制每次划分的特征选择迫使树互不相同，平均许多多样化的树可抵消各自的独立误差——把集成方差压到远低于任何单树，而偏差大致不变。

**实用好处：**
- *鲁棒性*——对离群值、混合特征类型和非线性交互宽容，几乎无需预处理（不需缩放）。
- *自带特征重要性*——来自不纯度下降或（更佳）置换重要性。
- *袋外（OOB）误差*——每棵树可在它未见过的 ~37% 行上验证，无需单独 holdout 即可免费估计验证。

**权衡：** 可解释性不如单树，比线性模型更大、服务更慢，且在表格基准上通常略逗弱于调优好的梯度提升。但因为它开箱即用、调优极少就表现良好，是理想的强大、低维护表格基线。

**要点：**
- Bagging + 随机特征子集 = 去相关树。
- 袋外样本免费给验证估计。
- 比 boosting 调优少；通常稍弱。
- 表格问题的鲁棒默认。

### 12. 梯度提升：XGBoost、LightGBM、CatBoost

**频率：** 高

**题目：** 请解释梯度提升，并对比 XGBoost、LightGBM 和 CatBoost。

**答案：** 梯度提升**顺序**建树，每棵都训练来校正至今集成的误差。具体地说，你计算损失关于当前预测的梯度（对平方误差而言就是残差），拟合一棵新的浅树到这些梯度，再乘以一个小**学习率**加入。反复此过程就是在函数空间做梯度下降。与 bagging（通过平均降方差）不同，boosting 通过不断拟合剩余降**偏差**——这正是提升树通常占据表格基准榜首的原因。

**三个主流库的创新不同：**
- **XGBoost**——使用**二阶**梯度（牛顿步）、内置 L1/L2 正则化、稀疏感知划分，以及面向并行的重度工程。鲁棒、经过实战检验的默认选择。
- **LightGBM**——**基于直方图**的分箱加**按叶**（best-first）生长而非按层生长，在大数据集上快得多。小数据上注意过拟合（限制 `num_leaves`）。
- **CatBoost**——通过有序目标编码**原生处理类别特征**，避免了朴素编码造成的目标泄漏，并使用对称树。当你有很多高基数类别且想要最少预处理时最佳。

**关键超参**及其相互作用：树数（在验证集上用 **early stopping**）、**学习率**（更小学习率 + 更多树泛化更好但训练更慢——共同调）、树大小（`max_depth` 或 `num_leaves`）、行/列**采样**作正则化，以及 L1/L2 惩罚。相对随机森林的权衡：boosting 更准确但对超参更敏感、更易过拟合，且其顺序性使训练更难并行化。

**要点：**
- 在残差梯度上顺序拟合树。
- LightGBM 最快；CatBoost 对类别最佳。
- 树数与 LR 共同调优并用 early stopping。
- 表格机器学习的金标准。

### 13. K-means 聚类

**频率：** 高

**题目：** K-means 聚类如何工作？它有哪些假设，何时改用替代方法？

**答案：** K-means 将 n 个点划分为 k 个簇，最小化到簇质心的**簇内平方距离之和**。**Lloyd 算法**交替两步直到分配不再变化：(1) *分配*每个点到最近质心，(2) *更新*每个质心为其分配点的均值。它快且总能收敛，但只能收敛到**局部**最优，所以初始化很重要。

**实用要点：**
- *选 k*——k 必须预先确定。用**肘部**法（惯性 vs k，找拐点）、**silhouette** 分数或 **gap statistic**。
- *初始化*——**k-means++** 把初始质心频开，避免随机播种造成的坏局部最小。跑多个种子取最优。
- *缩放*——因为用欧氏距离，务必**先标准化**特征，否则大尺度特征主导。
- *离群值*——均值对其敏感；可考虑 k-medoids。
- *规模*——mini-batch k-means 处理超大数据集。

**核心假设是球形、大小相近、线性可分的簇。**当簇为细长、密度变化或非凸时，K-means 会严重失败——改用 **DBSCAN/HDBSCAN**（基于密度，能找任意形状并标记噪声，无需 k）或**谱聚类**（用相似度图）。典型用途：客户分群、向量量化、图像颜色压缩和 anchor box 选择。

**要点：**
- 假设球形等大簇。
- k-means++ 初始化避免坏局部最小。
- 用肘部或 silhouette 选 k。
- DBSCAN/HDBSCAN 用于任意形状。

### 14. PCA：主成分分析

**频率：** 高

**题目：** PCA 如何工作？用于什么？有哪些局限？

**答案：** PCA 是**线性降维**，它找到一组新的正交轴——**主成分**——按它们捕获的数据方差量排序。第一个成分是最大方差方向，第二个是与之正交的最大方差方向，依此类推。投影到前几个成分就能在少得多的维度里保留大部分信号。

**计算：** 中心化数据，然后对数据矩阵做 **SVD**（数值上首选）或对协方差矩阵做**特征分解**。特征值给出每个成分解释的方差，因此可按"95% 方差"之类目标选择保留多少个。

**用途：** 可视化（投影到 2–3 维）、**去噪**（丢弃主要是噪声的低方差成分）、特征**去相关**，以及**压缩**以加速下游基于距离的模型。

**局限：**
- *仅线性*——无法捕捉弯曲流形；非线性结构用 **kernel PCA** 或**自编码器**。
- *成分不可解释*——每个都是所有原始特征的混合。
- *对缩放敏感*——必须**先标准化**，否则高方差特征会劫持成分。
- *无监督*——它最大化方差而非类别分离，被丢弃的成分可能携带标签信息而损害监督模型。

*可视化*非线性簇结构优先用 **t-SNE** 或 **UMAP**；带忠实重建的压缩 PCA 仍是主力。

**要点：**
- 沿正交轴最大化方差。
- 先标准化特征。
- 仅线性；非线性用 kernel PCA 或自编码器。
- 按累计解释方差选成分。

### 15. 反向传播

**频率：** 高

**题目：** 请解释反向传播及其主要的实际问题。

**答案：** 反向传播是**反向模自动微分**：在一次反向扫描中高效计算标量损失对*每个*参数的梯度。网络是一个操作的**计算图**；**前向**运行它产生激活与损失，**反向**按逆拓扑顺序遍历图，应用**链式法则**将 `dL/d(output)` 向后传播并在每个节点累加 `dL/d(param)`。

高效是关键：朴素地扰动 N 个参数中的每一个需 N 次前向，而反向模在**约 2 倍前向**的一次反向中就获得全部 N 个梯度。这才使训练十亿参数模型成为可能。PyTorch autograd、JAX、TensorFlow 等框架构图（动态或追踪）并自动运行。

**关键实际问题：**
- *数值稳定性*——指数和对数会上溢/下溢；用 **log-sum-exp** 等技巧和融合算子（如 softmax+交叉熵合算）。
- *梯度消失/爆炸*——深网中反复相乘使梯度缩小或放大；用 ReLU、batch/layer norm、残差连接和谨慎初始化缓解。
- *内存*——反向需要前向激活，所以内存随深度增长。**梯度检查点**用计算换内存：在反向时重算激活而非全部存储。

概念上反向传播"只是"系统化应用链式法则——但这种系统化应用是所有现代深度学习的基石。

**要点：**
- 链式法则的反向自动微分。
- 成本约 2 倍前向。
- 梯度检查点处理内存瓶颈。
- 稳定激活与归一化保持梯度流动。

### 16. 梯度下降变种：SGD、动量、Adam、AdamW

**频率：** 高

**题目：** 请比较 SGD、动量、Adam 和 AdamW。它们在何处泛化最佳？

**答案：** 它们都是梯度下降 `w := w - lr * grad` 的变体，区别在于如何利用梯度历史。

- **SGD（mini-batch）**——批次上的朴素更新。批间噪声是优点：它帮优化器逃离尖锐最小，常落入更平坦、泛化更好的最小。但纯 SGD 在峡谷和平台中很慢。
- **动量**——累积过去梯度的指数移动平均（β ≈ 0.9）并沿其前进。它在一致方向上加速、阻尼振荡，如重球滚下坡。**Nesterov** 动量在计算梯度前先看动量将带你去的地方，给出略好的修正。
- **自适应家族**——**Adagrad** 用累积平方梯度的逆平方根缩放每参数学习率（适合稀疏特征，但学习率衰减至零而停滞）。**RMSProp** 改用 EMA 而非求和修复了这点。
- **Adam**——结合**动量**（一阶矩）与 **RMSProp**（二阶矩）加早期的偏差校正。快、鲁棒、首选默认。
- **AdamW**——修复一个微妙 bug：在 Adam 的逐参数缩放下，把 L2 加进损失不等于真正的权重衰减。AdamW **解耦**权重衰减，直接作用于权重，提升泛化，现已成 Transformer 标配。

**经验法则：** 调优好的 **SGD + 动量**在计算机视觉中常泛化最佳；**Adam/AdamW** 主宰 NLP、Transformer 和大规模训练等看重对超参鲁棒性的场景。在所有这些中，**学习率是最重要的单个超参**——先调它，通常配 warmup 和衰减调度。

**要点：**
- SGD+动量：很多视觉场景下最佳泛化。
- Adam：收敛快，好默认。
- AdamW 修复 Adam 中权重衰减耦合。
- LR 是最重要的单个超参。

### 17. Batch Normalization

**频率：** 高

**题目：** 请解释 Batch Normalization：它做什么、推理时如何表现、有哪些陷阱？

**答案：** Batch norm **沿 batch 维**归一化层的前激活——对每个特征减 batch 均值、除以 batch 标准差——再应用**学习的缩放 `γ` 和平移 `β`**，使网络在有利时可撤销归一化。这保持激活在各层间良好缩放。

**好处：** 它稳定并加速训练，允许**更高学习率**，降低对初始化的敏感，并起轻度正则化作用（每个样本的归一化取决于它落入的随机 batch）。这是深层 CNN 变得易于训练的重要原因。

**推理时**无 batch 可计算统计量，所以 BN 使用训练时收集的均值与方差的**滑动（运行）平均**。这就是该层在训练 vs 评估模式下行为不同的原因。

**陷阱：**
- *依赖 batch size*——batch 很小时统计量噪声大，BN 退化；batch_size=1 时无用（某些微调场景）。
- *训练/评估模式 bug*——推理时忘调 `model.eval()`（或训练时忘调 `model.train()`）会用错统计量并静默地破坏准确率——经典 bug。
- *不适合序列*——变长 RNN/Transformer 激活没有稳定的 batch 分布。

**替代**（不沿 batch 归一化）：**layer norm**（每样本、沿特征——Transformer 标配）、**group norm**（沿通道组——适合小 batch 视觉）和 **instance norm**（每通道每样本——风格迁移）。BN 仍是 CNN 主干默认；LN 主宰 Transformer。

**要点：**
- 沿 batch 归一化；学习 gamma/beta。
- 小 batch 不好；改用 GroupNorm/LayerNorm。
- 训练/评估模式不匹配是经典 bug。
- CNN 用 BN；Transformer 用 LN。

### 18. 提示工程 vs RAG vs 微调：如何选型

**频率：** 高

**题目：** 产品团队想做一个 LLM 功能，问你应该投入到提示工程、RAG 还是微调。请讲讲你的决策思路。

**答案：** 第一步是诊断**差距的类型**，而不是先选技术。先问：模型缺的是**知识**（从没见过的事实，或会变化的数据），还是缺**行为**（稳定的格式、语气或技能）？这一个问题就能决定大部分选型。

**提示工程（含 few-shot）** 是默认起点。它免费、几分钟就能迭代，往往能拿到 80% 的效果。用清晰指令、用 system prompt 固定角色与约束，再用 2-5 个 few-shot 例子锁定格式。原型阶段先用它，花钱之前一定要先把它用尽——很多"我们需要微调"的问题，其实用更好的 prompt 加结构化输出（JSON schema / function calling）就解决了。局限：prompt 会越来越长（cost/latency 上升），且光靠文字教不会真正的新技能。

**RAG** 是解决**事实与时效性**的正确工具。当答案依赖私有文档、产品数据或任何会变的内容时，把知识放进向量库（如 pgvector、Pinecone、Qdrant）配合关键词/hybrid 检索，查询时把 top-k 片段注入 context。更新知识库，答案立刻变化——无需重训。它还能给出引用、降低幻觉。代价：检索基建、chunking/embedding 流水线，以及每次调用的 context token。

**微调（SFT / LoRA）** 更适合把**风格、格式或技能**固化进去——统一的品牌语气、严格的输出 schema、小众分类任务，或把长 prompt 压进权重以降低 latency。LoRA/QLoRA 让这件事很便宜（几百到几千条标注数据，单卡几小时）。经典错误是**用微调来加事实**：贵、事实会过时、且缺口处照样幻觉。事实 → RAG；行为 → 微调。

**它们可以组合。** 成熟系统常常同时用 RAG 和微调：微调负责领域措辞和可靠格式，RAG 负责实时知识。常见演进路径：prompt → prompt + RAG → 当 prompt 在行为上遇到瓶颈时再加微调。

**决策清单：** 需要实时/私有数据？→ RAG。输出格式/风格/技能必须稳定且 prompt 搞不定？→ 微调。只是验证想法？→ prompting。高并发且更短 prompt 能省真金白银？→ 微调压缩 context。也要权衡维护成本：prompt 改起来最便宜，RAG 需要数据流水线，微调在模型升级时要重训。

**要点：**
- 先诊断差距：知识/时效 → RAG；行为/风格/技能 → 微调；快速原型 → prompting。
- 先把提示工程（few-shot、结构化输出）用尽，再为 RAG 或微调付费。
- 别用微调加事实——贵、过时、仍会幻觉；该用 RAG。
- 成熟系统常组合使用；维护成本 prompt < RAG < 微调。

### 19. 梯度消失与梯度爆炸

**频率：** 高

**题目：** 什么导致梯度消失与梯度爆炸？如何修复？

**答案：** 反向传播通过链式法则将许多逐层雅可比矩阵**相乘**来计算梯度。若这些因子持续**小于 1**，乘积随深度指数缩小，梯度**消失**；若持续**大于 1**，乘积爆炸，梯度**爆炸**。饱和激活（sigmoid/tanh 压平到近零斜率）和小权重导致消失；大权重和循环导致爆炸。

**后果：** 消失阻止早期层学习（梯度几乎为零，权重冻结）；爆炸产生 NaN 使训练发散。

**缓解手段：**
- **ReLU 及变体**——正向无饱和，梯度为 1。
- **batch/layer 归一化**——保持激活良好缩放。
- **残差连接**——提供梯度高速路，让梯度绕过非线性直接流动。
- **合适初始化**（He/Xavier）——保持初始方差稳定。
- **梯度裁剪**——RNN/LLM 中将范数限在（如）1.0，直接阻止爆炸。
- **LSTM/GRU 门**——cell 状态中的恒定误差传送带。
- 通过**跳跃连接**缩短有效深度。

**诊断：** 早期发现爆炸容易（loss NaN）；消失更微妙——需监控每层梯度范数。现代 Transformer 训练结合 pre-norm、AdamW、warmup 和裁剪。

**要点：**
- 症状：loss NaN，早期层权重冻结。
- ReLU + 归一化 + 残差 + 裁剪 = 标准修复。
- LSTM 门专为消失而设计。
- 监控每层梯度范数。

### 20. 注意力机制

**频率：** 高

**题目：** 请解释注意力机制，以及为什么多头注意力有帮助。

**答案：** 注意力让序列中每个位置**根据内容从其他位置拉取信息**来构建自己的表示，而非固定窗口。每个 token 发出三个向量：**查询**（我在找什么）、**键**（我提供什么）和**值**（我携带的信息）。某位置的输出是所有值的加权平均，权重是该位置的查询与各键的匹配程度。

具体公式是**缩放点积注意力**：

`Attention(Q, K, V) = softmax(QK^T / √d_k) V`

`QK^T` 计算所有查询-键的两两相似度；除以 `√d_k` 防止点积过大（会把 softmax 推入饱和、低梯度区）；softmax 把它们变为和为 1 的权重；乘以 `V` 产生加权混合。在**自注意力**中，Q、K、V 都来自同一序列，所以 token 互相关注。

**多头注意力**并行运行 `h` 个注意力操作，每个有自己学习的投影，再拼接结果。这让不同头专业化——一个可跟踪句法依赖，另一个跟踪指代，另一个跟踪位置模式——一次捕捉多种关系类型而非将它们平均成单一模式。

难点在**成本**：计算所有两两交互在序列长度 `n` 上是 **O(n²·d)**，这就是长上下文工作追求稀疏、低秩和线性注意力近似（以及 FlashAttention 优化内存访问）的原因。用可跨位置完全并行的注意力取代循环，正是 Transformer 可扩展并取代 RNN 的关键。

**要点：**
- Softmax(QK^T / sqrt(d_k)) V。
- 多头捕获多种关系类型。
- O(n^2) 成本驱动长上下文研究。
- 自注意力在 Transformer 中取代循环。

### 21. 深度模型训练不收敛的排查

**频率：** 高

**题目：** 你开始训练一个深度网络，loss 就是降不下来——要么走平、要么剧烈震荡、要么几步之内变成 NaN。请讲讲你会如何系统性地排查。

**答案：** 黄金法则：**不要猜，要隔离。** 从最廉价、最常见的原因排到罕见的，每次只改一处。

**1. 先在单个 batch 上过拟合。** 在做任何事之前，取 4-8 个样本，训练到 loss 接近 0。这一个测试就能验证整条链路——模型、loss、optimizer、反向传播。如果你连一个小 batch 都*过拟合不了*，那 bug 在代码里而不是超参上，再怎么调 LR 也没用。仅这一步就能在几分钟内定位大多数「不收敛」问题。

**2. 检查数据。** 沉默的杀手。确认标签与输入对齐（有没有错位、取错列）、输入已归一化（zero-mean/unit-variance 或 /255）、数据已 shuffle（不是按类别排序）、原始特征里没有 NaN/inf。把几个解码后的样本连同标签可视化出来——人眼能抓到 assert 抓不到的问题。

**3. 检查 loss。** 确认它与任务匹配（CrossEntropy 期望 logits，却喂了已 softmax 的概率是经典错误）。核对初始 loss：C 个均衡类别下它应接近 **ln(C)**（10 类约 2.3）。初始 loss 离谱说明 logits 或 target 有问题。优先用数值稳定的形式（log-sum-exp、`BCEWithLogitsLoss`）。

**4. 学习率。** 头号超参。**太大 → loss 爆成 NaN 或震荡；太小 → 一条死平线。** 做 LR range test（在 1e-6→1e-1 间扫描并画 loss 曲线），取略低于发散点的值。transformer/大 batch 要加 warmup。

**5. 梯度。** 记录逐层 grad norm。**全为零 → 梯度消失**（dead ReLU、饱和的 sigmoid、初始化差）；**爆炸 → NaN**（clip 到约 1.0 的最大范数）。检查是否有 `detach()`/no-grad 把计算图截断了。

**6. 数值与精度。** FP16/混合精度容易溢出——用 loss scaling（GradScaler）或 bf16。一个孤立的 `sqrt(0)`、`log(0)` 或除零会污染下游一切；加上小 epsilon。

**7. 初始化与归一化。** 用合理的初始化（Kaiming/Xavier）。小 batch（<8）下 BatchNorm 统计量很噪——换成 GroupNorm/LayerNorm。

**8. train/eval 模式的坑。** 忘记 `model.train()`/`model.eval()` 会搞乱 BatchNorm 的 running stats 和 dropout，导致训练时 loss 看着正常、验证时却一团糟。

**要点：**
- 先在单个 batch 上过拟合——把代码 bug 与调参问题隔离开。
- 动超参之前先核验数据（标签、归一化、shuffle、NaN）。
- LR 是头号嫌疑：太大 → NaN/发散，太小 → 卡住；用 LR range test。
- 监控逐层 grad norm 并做 clipping；用 loss scaling 防 FP16 溢出。

### 22. CNN：卷积与池化

**频率：** 高

**题目：** 请解释 CNN 中的卷积与池化，以及 CNN 与 Vision Transformer 的对比。

**答案：** **卷积**在输入上滑动一个小的可学滤波器（卷积核），在每个位置计算点积产生**特征图**。三个性质使其强大高效：
- *权重共享*——同一滤波器处处应用，所以 3×3 滤波器无论图像多大都只有 9 个权重，而全连接层需百万个。
- *平移等变*——特征（边缘、纹理）无论出现在哪里都能被检测。
- *局部感受野*——每个单元只看一个小邻域；堆叠层增长有效感受野，从边缘→纹理→部件→物体逐层建层次。

**步幅、填充、空洞**控制几何：步幅 > 1 下采样，填充在边界保持空间尺寸，空洞在不加参数的情况下扩大感受野。

**池化**（最大或平均）下采样特征图，提供一定程度的平移*不变*并降低计算。现代架构常用**带步卷积**（学习下采样）取代池化。**1×1 卷积**在不动空间维度的情况下混合通道——ResNet 和 Inception 中使用的廉价瓶颈。

**CNN vs Vision Transformer：** ViT 把图像切成 patch 并应用自注意力，在数据量极大时可能胜过 CNN，因为它们内置假设（**归纳偏置**）更弱。但同样的缺乏偏置意味着 ViT **渴数据**；在中小数据集上 CNN 的局部性和权重共享先验胜出，混合设计（卷积 stem、ConvNeXt）常给出最佳的效率-准确权衡。

**要点：**
- 权重共享 + 局部性 = 参数效率。
- 池化提供平移不变性。
- 1x1 卷积用于通道混合/瓶颈。
- ViT 有竞争力但卷积在小数据上仍强。

### 23. RNN、LSTM、GRU

**频率：** 高

**题目：** 请比较 RNN、LSTM 和 GRU，并解释为什么 Transformer 大致取代了它们。

**答案：** **RNN** 逐步处理序列，维护一个向前传递信息的**隐状态**：`h_t = f(W·x_t + U·h_{t-1})`。优雅，但跨多步反向传播会相乘许多雅可比，所以**朴素 RNN 遭受梯度消失/爆炸**，无法学习相隔几步以上的依赖。

**LSTM** 用一个独立的 **cell 状态**修复这点，cell 状态只经加法、门控的修改流过时间——"恒定误差传送带"。三个 sigmoid **门**控制它：**遗忘**门决定从 cell 丢弃什么，**输入**门决定加入什么，**输出**门决定暴露什么为隐状态。因 cell 路径基本线性，梯度在长跨度上存活，支持真正的长期记忆。

**GRU** 简化 LSTM：把遗忘和输入门合并为单个**更新**门，并绑定 cell 与隐状态。参数更少、更快，性能通常与 LSTM 相当——想要 RNN 时的常见默认。

**双向**变体前向一遍后向一遍并拼接状态，给每个位置同时提供过去和未来上下文——但只能用于整个序列可得的**非流式**任务。

**为什么 Transformer 胜出：** RNN 本质上是**顺序的**，无法在 GPU 上跨时间步并行，连 LSTM 也难以处理极长程依赖。自注意力一次性看到所有位置（可并行、直接的长程连接），这就是 Transformer 自 2017–2018 起在多数 NLP 和语音中取代 RNN 的原因。RNN 仍出现在**流式/低延迟**和**端上**场景，因为其每步恒定成本和小占用很重要。

**要点：**
- LSTM 门修复朴素 RNN 的消失。
- GRU 比 LSTM 简单，性能相近。
- 顺序 = 难以在 GPU 上并行。
- 2018 后多被 Transformer 取代。

### 24. Transformer 架构

**频率：** 高

**题目：** 请描述 Transformer 架构以及自 2017 年以来的主要升级。

**答案：** Transformer（出自《Attention Is All You Need》，2017）由堆叠的相同块构成；一个**块**是多头自注意力后接**位置式前馈网络**（两个线性层夹一个非线性），每个子层包裹在**残差连接 + LayerNorm** 中。注意力**跨**位置混合信息；FFN 独立变换每个位置。

**编码器 vs 解码器：** **编码器**用双向自注意力（每个 token 看到所有其他 token）。**解码器**多加两样：**掩码**自注意力（token 只能关注更早的位置，无法偷看它要预测的未来 token）和**交叉注意力**（解码器的查询关注编码器输出）。因注意力与顺序无关，**位置编码**（正弦或学习的）注入序列顺序。

**三种变体对应三种用途：**
- **仅编码器**（BERT）——双向理解：分类、NER、检索。
- **仅解码器**（GPT、LLaMA）——自回归生成；现主导 LLM。
- **编解码器**（T5、BART）——序列到序列：翻译、摘要。

**自 2017 以来的现代升级**，在 LLaMA 系模型中最明显：**pre-norm**（子层前做 LayerNorm，稳定深层训练）、**RMSNorm**（更廉价的归一化）、**RoPE**（旋转位置嵌入，编码相对位置并外推到更长上下文）、**GQA/MQA**（分组/多查询注意力，共享 KV 头以缩小 KV 缓存、加速推理）、**SwiGLU** FFN 和 **FlashAttention**（IO 感知的精确注意力核，消除内存瓶颈）。值得注意的是核心块保持惊人稳定——多数进展来自**规模、数据和小调整**而非重新设计。

**要点：**
- 注意力 + FFN + 残差 + LayerNorm = 一个块。
- 按任务选编码器、解码器或两者。
- RoPE、GQA、SwiGLU 是现代标准升级。
- 架构自 2017 稳定；规模是真正主力。

### 25. 迁移学习与微调

**频率：** 高

**题目：** 请讲解迁移学习与微调。主要有哪些策略和技巧？

**答案：** 迁移学习把**在大型通用数据集上预训练的模型**复用为较小相关任务的起点——你继承通用表示（边缘/纹理，或语言结构）而非从零学习，这就是它成为几乎每个现代应用默认做法的原因。

**沿一条谱系的三种策略：**
- *特征抽取*——**冻结主干**，替换并只训练一个新任务头。快、廉价，目标数据集小或与源非常相似时最佳。
- *全微调*——用低学习率更新**所有**参数。数据充足时上限最高，但有**灾难性遗忘**预训练知识的风险。
- *逐层/渐进解冻*——先训头，再自顶向下解冻各层。折中方案。

**NLP 中**微调 BERT/GPT 系模型用于分类、NER 或 QA；**视觉中**微调 ImageNet/JFT/CLIP 主干用于检测或分类。

**关键技巧：**
- 对预训练层用**低得多的 LR**（比从零头小 10–100 倍），只轻推而非摧毁已学权重。
- **判别式 LR**——早期（通用）层更低，后期（任务特定）层更高。
- **warmup** 避免早期大步破坏权重。
- 数据稀缺时**冻结早期层**；加 dropout/权重衰减对抗遗忘。

对 LLM，**参数高效微调（PEFT）**——LoRA、adapter——已大致取代全微调，在只训练极小部分权重、适配普通硬件的同时匹配其质量。

**要点：**
- 预训练主干 + 任务头 = 标准配方。
- 预训练权重用较低 LR。
- LoRA/PEFT 替代 LLM 的全微调。
- 通过谨慎 LR/冻结缓解灾难性遗忘。

### 26. LoRA 与参数高效微调（PEFT）

**频率：** 高

**题目：** 请解释 LoRA 及参数高效微调（PEFT）。为什么 LoRA 成为主导？

**答案：** 大模型的全微调会更新每个权重，且必须为所有权重存储优化器状态（动量 + 方差）——对 70B 模型这是数百 GB 的 GPU 内存，多数人无法企及。PEFT 方法冻结预训练权重，只训练**少量新参数**。

**LoRA（低秩适配）**基于一个观察：任务所需的*更新*是低秩的。它**冻结原权重 `W`**，学习两个小矩阵 `A`（d×r）和 `B`（r×d），其乘积即更新：有效权重变为 `W + BA`，秩 `r ≪ d`（通常 r = 8–64）。只有这些矩阵训练——约**参数的 0.1–1%**——但在许多任务上质量接近全微调。

**QLoRA** 在内存上更进一步：它把**冻结的基模量化到 4-bit**（NF4），在其上训练全精度 LoRA 适配器，让你在**单块 48GB GPU** 上微调 65–70B 模型。

**其他 PEFT 方法：** **adapter**（插入每层的小瓶颈模块）、**prefix tuning**（前置到注意力键/值的可学向量）和 **prompt tuning**（可学软提示嵌入）。

LoRA 胜出源于实用优势：它**不增加推理延迟**（训练后适配器可**合并**回 `W`），你可为一个基模保留许多小的任务特定适配器并**切换**它们，且生态/工具支持广泛。自 2023 起它一直是定制 LLM 的默认方式。

**要点：**
- 训练低秩 delta 而非全权重。
- QLoRA：4-bit 基 + LoRA = 消费级 GPU 微调。
- 适配器可合并至基模实现零成本推理。
- 2023 起 LLM 定制的默认。

### 27. RLHF：来自人类反馈的强化学习

**频率：** 高

**题目：** 请讲解 RLHF 流水线。为什么 DPO 成为更简单的替代？

**答案：** RLHF（来自人类反馈的强化学习）是把原始预训练 LLM 变成有用、对齐助手的**后训练**过程。它有三个阶段：

1. **监督微调（SFT）**——在精选的高质量「指令 → 响应」**示范**集上微调基模，教它遵循指令的格式与行为。
2. **奖励模型（RM）**——收集带**多个**候选响应的提示，让人类对它们**排序**。训练一个单独模型预测这些偏好，通常用 **Bradley-Terry** 目标（某响应被偏好的概率是奖励差的逻辑函数）。RM 把模糊的人类判断变成标量分数。
3. **PPO（RL）优化**——用强化学习微调 SFT 模型以**最大化奖励模型分数**，同时加一个 **KL 散度惩罚**防止策略偏离 SFT 模型太远。这个惩罚至关重要：没有它模型会**奖励黑客**（利用 RM 的怪癖），输出多样性**坍塌**。

**优势：** 它对齐用手写示例或固定损失难以捕捉的**主观品质**——有用性、无害性、语气。GPT-3.5/4、Claude 和 Gemini 就是这样对齐的。

**弱点：** 流水线**复杂且不稳定**（训练与部署单独的 RM、调 PPO），且易发生**奖励黑客**、**mode collapse** 和**过度奉承**（因评分者奖励了迎合，模型倾向说用户想听的）。

**DPO（直接偏好优化）**为简化而生：它推导出一个直接在偏好对上训练的损失，**完全跳过显式奖励模型和 RL 循环**。它更稳定、更易运行且质量相当，这就是 DPO 及其后继者（IPO、KTO、ORPO）如今常见的原因。

**要点：**
- SFT → 奖励模型 → PPO。
- KL 惩罚控制分布漂移。
- 对齐示范之外的主观品质。
- 复杂；DPO 是现代更简单替代。

### 28. LLM 中的幻觉

**频率：** 高

**题目：** 什么导致 LLM 产生幻觉？如何缓解？

**答案：** 幻觉是 LLM 产生**自信、流畅但事实错误或完全编造的文本**——捧造的引用、胡编的统计、看似合理但不存在的 API。危险正在于它*听起来*权威，所以能滑过随意审阅。

**根本成因：**
- *训练目标*——模型被训练预测**最合理**的下一个 token，而非最*真实*的。流畅与事实是不同的目标。
- *在知识缺口上插值*——在模型缺少知识处，它用见过的模式混合填空，产生模式上像真却不真的东西。
- *数据错误*——预训练语料本身包含错误和矛盾。
- *指令调优偏置*——模型因有用、回答而获奖，这推动它猜测而非说"我不知道"。

**缓解手段：**
- **检索增强生成（RAG）**——用检索的源文档 grounding 答案，让模型引用而非回忆；最大的单个杆杆。
- **引用/归属提示**——要求模型引用来源，使无支撑的声明可见。
- **受限/结构化解码**——强制输出为 schema 或合法语法。
- **思维链 + 验证**和**自洽**（采样多个答案取多数）减少推理错误。
- **放弃训练**——教模型说"我不知道"，并用**不确定信号**（token logprob、语义熵）标记低置信答案。
- **事后事实检查器**——LLM-as-judge 或对输出做检索校验。

前沿模型幻觉更少但永不为零，尤其在 niche 主题、近期事件和对抗提示上——所以**幻觉抗性应是一等评估指标**，与推理、指令遵循并列追踪，而非事后补救。

**要点：**
- 自信、合理但错误的输出。
- RAG 与引用是顶级缓解。
- 自洽与放弃有帮助。
- 把幻觉当一等指标评估。

---

### 29. 检索增强生成（RAG）

**频率：** 高

**题目：** 请解释 RAG：流水线、相对微调的优势以及失败模式。

**答案：** 检索增强生成通过**在查询时获取相关文档并把它们注入提示**作为上下文来回答，让模型基于提供的事实推理而非只靠冻结的参数记忆。这让它能在**私有、最新或极大**的语料上回答而无需重训。

**流水线有两个阶段：**
- *索引（离线）*——把文档**分块**为段落，把每块**嵌入**为向量，存入**向量数据库**（FAISS、Pinecone、pgvector、Weaviate）。
- *查询（在线）*——**嵌入查询**，按向量相似度**检索 top-k** 最近块（常与关键词/BM25 结合做**混合检索**），可选用交叉编码器**重排**提升精度，把块**组装**进提示，并**生成**带**引用**（指回源）的答案。

**相对微调：** RAG 是处理**事实与时效**的正确工具——更新知识库答案立即改变，且内置可验证的**归属**。微调更适合烘入**风格、格式或技能**。两者互补，多数生产 "LLM 应用" 都是 RAG。

**常见失败模式：**
- *检索遗漏*——正确的块不在 top-k，模型无可 grounding。
- *分块边界差*——在想法中间切开断了回答所需上下文。
- *不相关检索*——跑题的块分散或误导模型。
- *提示注入*——检索内容中嵌入的恶意指令劫持模型。

实用经验：**检索质量通常比选哪个 LLM 更重要**——先投入分块、嵌入、混合检索和重排。

**要点：**
- 检索把生成 grounding 到外部源。
- 管道：分块 → 嵌入 → 检索 → 重排 → 生成。
- 事实/时效上比微调好。
- 检索质量常是瓶颈。

### 30. 智能体与工具使用

**频率：** 高

**题目：** 什么是 LLM 智能体与工具使用？主要模式和生产挑战有哪些？

**答案：** **智能体**通过跑一个**循环**超越单次生成：对目标推理、采取行动（调用工具）、观察结果、决定下一步——重复直到完成。工具给模型它本身缺乏的能力：网搜获取新事实、代码解释器做精确计算、数据库或 API 调用做真实动作。

**主要模式：**
- **ReAct**——交错显式**推理**轨迹与**行动**，模型"想出声"后再根据该想法行动。
- **函数/工具调用**——模型发出**结构化 JSON** 命名工具及参数；运行时执行并把结果回馈。这是 GPT、Claude、Gemini 暴露的标准接口。
- **计划与执行**——规划器先起草多步计划，执行器再跑步骤（复杂任务上优于逐步决定）。
- **反思**——模型批评自己的输出并修订。
- **多智能体**——专门智能体（研究者、编码者、审查者）协作；AutoGen、CrewAI 等框架编排这一切。

框架（LangChain、LlamaIndex、OpenAI Assistants）提供围绕这些循环的编排、工具注册表和记忆。

**生产挑战：**
- *延迟*——每步都是一次往返；多步轨迹很慢。
- *成本*——长推理轨迹和重复上下文燃烧 token。
- *可靠性*——智能体可能循环、卡住或误用工具；需步数限制和错误处理。
- *评估*——给多步轨迹评分比给单一答案评分难得多。
- *安全*——作用于现实世界的工具（发邮件、跑代码、花钱）需护栏和确认。

智能体在**下一步真正取决于前一结果**时发光；对固定工作流，单次调用或硬编码流水线更廉价、更可靠。

**要点：**
- 推理 → 调工具 → 观察 → 重复。
- 函数调用是标准接口。
- 延迟、成本、评估是实用挑战。
- 多步自适应 > 许多任务单次。

### 31. 模型监控与漂移检测

**频率：** 高

**题目：** 如何在生产中监控模型并检测漂移？

**答案：** 部署的模型会随世界偏离其训练分布而**静默退化**——准确率下降却无错误、无崩溃、除非你监看否则无告警。监控捕捉这一点。

**四种不同的漂移：**
- *数据（协变量）漂移*——输入特征分布移动（如新的用户人群）。`P(X)` 变化。
- *概念漂移*——输入与目标的关系变化（欺诈手法演变，同样特征现在含义不同）。`P(y|X)` 变化——最危险的一种。
- *预测漂移*——模型的**输出**分布移动，尚无标签时的有用代理。
- *性能漂移*——实际准确率/AUC 下降，只有**真实标签到达**（常有延迟）后才可测。

**检测方法：** **PSI**（人群稳定性指数）和 **KL 散度**测分布偏移，**Kolmogorov-Smirnov** 检验连续特征，**ADWIN** 用于流式数据，**嵌入漂移**用于图像/文本（比较嵌入分布）。

**重要实践：**
- **按特征和按段**追踪漂移，而非只看全局——某国家或设备类型的回归在全局指标中被平均掉，却伤害真实用户。
- 设带**迟滞**的警报（要求持续偏差）避免噪声误报。
- 也监控运维健康：**延迟、错误率、吞吐量**。

工具：Evidently、Arize、WhyLabs、Fiddler、Datadog ML。关键在于，**没有响应计划的漂移检测只是个警报**——把它与自动重训触发器或人工审查/分诊工作流配套，使检测真正导向修复。

**要点：**
- 数据、概念、预测、性能漂移不同。
- PSI/KL 测分布偏移。
- 按段监控捕获局部退化。
- 检测与重训或人工分诊配套。

### 32. 交叉验证策略

**频率：** 中

**题目：** 请比较主要的交叉验证策略。各自适合什么时候？

**答案：** 交叉验证通过轮换保留哪部分数据来估计模型的**泛化**能力，比单次训练/测试划分更稳定、更不靠运气。关键是选择尊重数据**依赖结构**的方案——选错会泄露信息、虚高分数。

**核心方案：**
- **k 折**——切成 k 等份；用 k−1 训练、保留的一折验证，跨 k 个分数平均。k=5 或 10 是标准。所有数据都用于训练和验证。
- **分层 k 折**——同上，但每折保持**类别比例**。这是**分类的默认**，类别不平衡时必不可少（否则某折可能几乎没有少数类样本）。
- **留一法（LOO）**——k = n，每次保留单个样本。几乎无偏但**方差大且昂贵**；仅用于极小数据集。
- **重复 k 折**——用不同随机划分跑多次 k 折并平均，稳定估计。

**简单 k 折何时会错：**
- **嵌套 CV**——当你*也*调超参时，**内**循环选超参、**外**循环评估。在同一批折上调参与评估会给出**乐观偏差**的分数；嵌套修复它。
- **时间序列（TimeSeriesSplit）**——**绝不能在未来上训练**。用前向链式的扩展或滑动窗口，总在比训练更晚的时间戳上验证。
- **分组/聚簇数据（GroupKFold）**——当行共享分组（每患者多次就诊、每用户多张照片）时，把整组完全放训练**或**验证。把一组拆到两边会**泄露**身份特定信号。

经验法则：让折的结构匹配数据实际的相关方式，以及你真正要回答的问题。

**要点：**
- 分层 k 折是分类的安全默认。
- 嵌套 CV 用于诚实的超参选择。
- 时间序列需要前向链式划分。
- 分组折避免聚类数据中的泄漏。

### 33. 损失函数：何时用哪种

**频率：** 中

**题目：** 如何为不同任务选择损失函数？

**答案：** 损失定义了对优化器而言*"错"意味着什么*，所以它必须**同时匹配输出类型和不同错误的成本**。两条铁律：不要用回归损失做分类，反之亦然。

**回归损失**主要在**离群敏感度**上不同：
- **MSE（L2）**平方误差，大错误主导梯度——大错误确实很糟时很好，但**离群值可能劫持训练**。
- **MAE（L1）**是线性的，所以**对离群值鲁棒**，但梯度恒定，在最小值附近难优化。
- **Huber** 混合两者：小残差用二次（平滑），大残差用线性（鲁棒）——有离群值但仍想要平滑梯度时的好默认。

**分类损失：**
- **二元/分类交叉熵（log loss）**是概率输出的标准（多分类配 **softmax**）。关键是，最小化 log loss 产生**良好校准的概率**——预测 0.7 真的意味着约 70%。
- **Hinge loss**（SVM 式）最大化间隔，但产生**分数而非校准概率**。

**专门损失：**
- **Focal loss**——降低易分好样本的权重，使训练聚焦难例；**极端不平衡**（密集目标检测）的首选。
- **排序**——相对顺序比绝对分数更重要时用 pairwise（RankNet）或 listwise（LambdaRank、ListNet）。
- **嵌入**——对比、triplet 或 InfoNCE 损失把相似项拉近、不同项推远。
- **检测**——focal + IoU/GIoU 等组合处理分类加定位。

总把损失回溯到错误的**业务成本**：若漏报代价是误报的 10 倍，就相应加权损失，而非优化原始准确率。

**要点：**
- 损失须匹配输出类型与错误成本。
- 交叉熵校准概率，hinge 不会。
- Huber/MAE 适用于离群多的回归。
- focal loss 适用于极端类别不平衡。

### 34. ROC 与 PR 曲线：何时用哪个

**频率：** 中

**题目：** 请对比 ROC 与 PR 曲线。何时该用哪个？

**答案：** 两条曲线都**跨所有阈值**概括分类器性能，但回答不同问题，在类别不平衡下行为迥异。

**ROC 曲线**随阈值从 0 扫到 1，绘制**真阳性率**（召回）vs **假阳性率**；**ROC-AUC** 是其下面积，等于模型把随机正例排在随机负例之上的概率。关键性质：因 FPR 由*负例*数归一化，ROC-AUC **对类别平衡不变**——无论正例占 50% 还是 0.1% 分数相同。

**PR 曲线**绘制**精确率** vs **召回率**。精确率取决于*预测*为正的数量，所以 PR-AUC **对正例比例敏感**——它直接反映正类有多稀少。

**为什么在严重不平衡下重要：** 假设 0.1% 的交易是欺诈。模型可能得 **ROC-AUC 0.95** 仍然无用，因为即使在庞大负例池上很小的 FPR 也产生洪水般的误报——所以**可用召回处的精确率惨不忍睹**。PR 曲线立即**暴露**这一点；ROC 曲线则隐藏它。

**所以：**
- 大致**平衡**的问题，或想要**平衡不变**指标跨数据集比较模型时，用 **ROC-AUC**。
- **正例稀少**且精确率重要时用 **PR-AUC**——欺诈、疾病筛查、信息检索、点击预测。

记住：两者都在*所有*阈值上汇总。部署仍需根据误报 vs 漏报的真实成本**选一个运营阈值**，再在该阈值处检查**混淆矩阵**。

**要点：**
- ROC-AUC 与平衡无关；PR-AUC 与之有关。
- 正例稀少时用 PR-AUC。
- 两者汇总阈值选择；仍须挑一个。
- 与部署阈值下的混淆矩阵配套使用。

### 35. 表格业务问题的端到端建模

**频率：** 中

**题目：** 拿一个具体的表格业务问题 —— 比如客户流失（churn）或信贷违约（credit default）预测 —— 讲一遍你从问题定义到上线、监控的完整流程。你的精力实际花在哪？

**答案：** 先说实话：在表格问题上，回报在**问题定义、数据/特征、评估**上 —— 而不在花哨模型上。一个调好的 gradient booster 配干净、无泄漏的特征，几乎每次都能打赢炫技的神经网络。

**1. 围绕决策来定义问题。** "预测 churn"不是需求。要定死预测窗口（未来 30 天是否流失？）、人群，以及最关键的 —— **与行动挂钩的指标**。如果业务是对 top-N 高风险客户外呼，你在意的是 **precision@k**，不是原始 accuracy。仔细定义标签，以及特征在哪个时间点是已知的。

**2. 先做 baseline。** 从一个朴素启发式规则起（如"30 天未登录记为高风险"）设下限，再上 **logistic regression**。baseline 能尽早暴露数据问题，也告诉你复杂模型到底值不值得做。

**3. 主力：gradient boosting。** **XGBoost / LightGBM / CatBoost** 是表格的默认选择。它们几乎不用预处理就能吃混合类型、缺失值和非线性交互。只有当数据量极大或有丰富文本/序列特征时，才考虑深度学习。

**4. 无泄漏的特征与切分 —— 价值最高的活。** feature engineering（聚合、比率、recency、趋势）贡献大部分收益。头号翻车点是 **leakage（数据泄漏）**：用到未来信息的特征，或在时序问题上做随机切分。只要有时间维度，就用 **time-aware split**（用过去训练、用未来验证）。核查没有由 target 派生的特征混进来。

**5. 不平衡与调参。** 类别偏斜时用 class weights / `scale_pos_weight`，别盲目过采样。用交叉验证（Optuna / random search）调超参，但别过度投入 —— 模型很少是瓶颈。

**6. 校准与阈值。** 业务决策需要可信概率，所以要**校准（calibration）**（Platt / isotonic）并看 reliability curve。再从行动的成本/收益去选**工作阈值**，而非默认 0.5。

**7. 误差分析（error analysis）。** 按细分人群切开看性能，找它在哪失效。这比再来一轮调参能挖出更多改进。

**8. 离线 → 线上 → 部署 → 监控。** 先离线验证，再用 **A/B test** 或 shadow 跑确认 —— 离线的提升到线上常常缩水。按场景部署为 **batch scoring**（churn 可每夜跑）或 **real-time**（若决策是逐请求的）。上线后**监控** feature drift、分数分布与真实表现，并安排**重训（retraining）**。

**要点：**
- 回报在问题定义、无泄漏特征与评估上，而非花哨模型；gradient boosting 是表格主力。
- 指标要与决策挂钩（如 precision@k），从启发式 + logistic regression baseline 起步。
- 用 time-aware split 防 leakage；校准概率并按业务成本/收益选阈值。
- 先离线验证再用 A/B 确认，按需 batch 或 real-time 部署，配 drift 监控与定期重训。

### 36. 为业务问题设计评估指标与验证方案

**频率：** 中

**题目：** 产品团队让你为一个真实业务问题建模——比如标记欺诈交易。你如何决定要优化什么指标，以及在信任它之前如何验证？

**答案：** 指标不是从教科书里挑的——它是**从决策及其代价推导出来的**。从这里出发。

**1. 从决策和错误代价出发。** 先问：一次预测触发什么动作，每种错误代价多少？欺诈场景里，**漏报**（漏掉欺诈）的代价是拒付金额；**误报**（拦下正常交易）的代价是激怒客户、损失营收。这些代价是非对称且通常不相等的，这就立刻否决了朴素 accuracy——欺诈率 0.5% 时，一个「永远判非欺诈」的模型有 99.5% accuracy 却毫无用处。

**2. 选一个能反映该代价的指标。**
- *不平衡分类：* 用 **PR-AUC** 和**某个工作点上的 precision/recall**，而非 ROC-AUC（它在稀有正例上会虚高）。用 **F-beta** 按代价比例侧重 recall 或 precision。
- *排序 / 推荐：* **NDCG、MAP、recall@k**——用户只看列表顶部。
- *概率要喂给决策或定价：* **校准**（reliability curve、Brier、ECE）与区分度同样重要——「0.9」必须真的意味着 90%。
- *回归：* 让 loss 匹配代价——误差线性缩放用 MAE，高估/低估代价不同用 quantile loss。

**3. 警惕 Goodhart / 代理偏离。** 指标是业务目标的**代理**；把它优化到极致可能反而偏离目标。全部拦截能最大化欺诈 recall，却摧毁营收。用 **guardrail 指标**防范——即次级约束（通过率、延迟、客诉），在优化主指标时它们不能退化。

**4. 设计能镜像生产的验证方案。** 划分必须反映模型真实的使用方式：
- **按时间划分**——任何时序问题都用过去训练、未来验证；绝不跨时间 shuffle。
- **分组感知划分**——让同一用户/商户不同时出现在训练与测试（防泄漏）。
- **分层（stratify）**——在每个 fold 中保持稀有类别比例。

**5. 对齐离线与线上，并选定阈值。** 确认离线指标与业务 KPI 同向变化，再从代价曲线（或某个 precision/recall 目标）选定**工作阈值**，而不是默认的 0.5。最后，用衡量真实业务结果的**线上 A/B 测试**验证整条链路。

**要点：**
- 从决策及 FP 与 FN 的非对称代价推导指标——不平衡场景下 accuracy 通常是错的。
- 指标要匹配任务：不平衡用 PR-AUC/F-beta，排序用 NDCG，概率驱动决策时看校准。
- 用能镜像生产的验证：时间感知、分组感知、分层划分。
- 加 guardrail 指标防 Goodhart，按代价调工作阈值，并用 A/B 测试确认。

### 37. 机器学习项目生命周期

**频率：** 中

**题目：** 请讲解机器学习项目生命周期。多数项目实际在哪里失败？

**答案：** ML 项目是一个循环而非直线，且建模是*便宜*的部分。阶段：

1. **问题界定与指标设计**——模型改进什么**决策**？什么**指标**捕捉成功，要击败的**基线**（常是简单启发式）是什么？这里错了下游全部完蛋。
2. **数据采集与标注**——采集、清洗、标注数据；建立标签质量与一致性。
3. **探索性数据分析（EDA）**——理解分布、缺失、泄漏风险和分段行为。
4. **特征工程与划分**——构建特征并创建**无泄漏**、镜像生产的训练/验证/测试划分。
5. **基线模型**——最简单的可行方案，设下下限并端到端验证流水线。
6. **迭代建模**——用恰当验证改进，由**错误分析**（看*哪些*案例失败及原因，而非只看汇总分）引导。
7. **校准与阈值调整**——在正确运营点把分数变成决策。
8. **离线评估**——在镜像生产的留出集上。
9. **线上 A/B 测试**——对比当前生产系统，唯一真正算数的测试。
10. **监控**——数据漂移、性能、公平性——加上**重训节奏**，最终**下线**。

**项目实际失败几乎总在上游：** 界定了错误问题，数据**泄漏**（虚高离线指标），离线与线上指标**不匹配**，或**无监控**使静默退化无人察觉。教训：把大部分时间花在**数据质量和评估**上，而非追逐 0.5% 的 AUC——一个界定良好、数据干净、评估诚实的问题胜过根基不稳上的花哨算法。

**要点：**
- 问题界定与指标设计决定成败。
- 线上 > 线下；信任模型前先做 A/B。
- 监控与重训练是生命周期的一部分。
- 数据质量胜过花哨算法。

### 38. 支持向量机

**频率：** 中

**题目：** 支持向量机如何工作？它们有哪些局限？

**答案：** SVM 寻找**最大化间隔**的超平面——决策边界与每类最近点之间的距离。这个最大间隔选择倾向于良好泛化，而且只有最近的点——**支持向量**——真正决定边界；更远的一切与解无关。

**两个关键机制：**
- **软间隔（`C`）**——真实数据非完美可分，所以 `C` 在**间隔宽度与误分类**之间权衡。小 `C` = 更宽间隔、更容忍错误（更多正则化）；大 `C` = 更用力拟合训练数据（过拟合风险）。
- **核技巧**——为得到**非线性**边界，核（RBF、多项式、线性）**隐式**地在高维空间计算内积，而无需真正展开特征。这使复杂边界可行，是 SVM 的标志思想。

**SVM 擅长之处：** **高维**问题，尤其**特征多于样本**时——经典情形是用 TF-IDF 向量的**文本分类**。

**局限：**
- **扩展**——训练约 `O(n²)`–`O(n³)`，所以超过约 10 万样本后卡顿。
- **敏感**——核选择与超参（`C`、`gamma`）强烈影响结果，需细心调优。
- **无原生概率**——输出是带符号距离而非校准概率；需 **Platt scaling** 获取。

SVM 已大致被**树集成和神经网**取代，但在**小型高维**数据集上仍是强选择。

**要点：**
- 最大化间隔，由支持向量决定。
- 核技巧实现非线性边界。
- 不可扩展超过约 10 万样本。
- 需 Platt scaling 输出概率。

### 39. K 最近邻

**频率：** 中

**题目：** K 最近邻如何工作？它的主要敏感点有哪些？

**答案：** KNN 是**惰性学习器**：通常意义上没有训练阶段——它只是**存储所有训练数据**。预测时找到查询的 **k 个最近训练样本**（用距离度量——欧氏、曼哈顿或余弦）并组合其标签：分类用**多数投票**，回归用**平均**。全部工作发生在推理时。

这个设计翻转了通常的成本结构：**训练免费，但推理昂贵**——朴素查找每查询 `O(n)`，因为要与每个存储点比较。为实用化需给数据**建索引**：低维用 **KD-tree** 或 **ball tree**，高维大规模用 **HNSW 或 FAISS** 等**近似最近邻（ANN）**结构。

**三个需注意的敏感点：**
- **特征缩放**——距离被大量级特征主导，未缩放的特征会淡没其他。**先归一化/标准化**。
- **维度灾难**——高维下点间距离**集中**（一切变得大致等距），"最近"失去意义，KNN 退化。
- **`k` 的选择**——经典偏差-方差旋钮：**小 `k`** = 低偏差、高方差（噪、对离群敏感）；**大 `k`** = 更平滑但高偏差。用交叉验证调。

直接分类方面，学习模型已大致取代 KNN。但其核心操作——找最近向量——如今在**检索中至关重要**：基于嵌入的推荐系统、语义搜索和 RAG 都依赖对嵌入的 ANN 搜索，这就是大规模的 KNN。

**要点：**
- 无训练；无索引时推理慢。
- 必须缩放特征；用 CV 选 k。
- 高维下表现差。
- ANN 库（FAISS、HNSW）使其在检索中可扩展。

### 40. 朴素贝叶斯

**频率：** 中

**题目：** 朴素贝叶斯如何工作？尽管有"朴素"假设，为何在文本上效果好？

**答案：** 朴素贝叶斯用**贝叶斯定理**分类——`P(类|特征) ∝ P(类) × P(特征|类)`——取后验最大的类。**"朴素"**部分是简化假设：所有特征**给定类时条件独立**，从而把难算的联合 `P(特征|类)` 变成各特征概率的简单乘积。

**针对不同特征类型的三种变体：**
- **高斯 NB**——连续特征，每类建模为正态分布。
- **多项式 NB**——**词频**；文本（垃圾邮件、情感、主题）的主力。
- **伯努利 NB**——二元存在/缺失特征。

**为何如此快：** 训练是**闭式**的——单次扫描只需计数并归一化频率。无迭代优化，内存极小，易于增量更新。

**为何假设为假仍对文本有效：** 句中词显然*不*独立，朴素贝叶斯却仍分类良好。原因是分类只需模型把 **argmax** 选对，而非精确概率——即使独立假设错误，正确类通常仍赢得比较。高维词袋数据正好发挥这一优势。

**主要弱点是校准：** 因为它把许多实际相关的"独立"概率相乘，会**重复计数证据**并产生**过自信**概率（推向 0 或 1）。所以信任它的*排序/标签*，而非原始概率。

它在正经 NLP 上已被逻辑回归和 Transformer 分类器超越，但近乎零成本使它仍是文本与小数据问题的极佳**基线**。

**要点：**
- 假设特征独立；很少为真但常奏效。
- 一次扫描完成训练；极快。
- 概率未良好校准。
- 文本与小数据分类的最佳基线。

### 41. 学习率调度

**频率：** 中

**题目：** 请解释学习率调度以及它为何重要。

**答案：** **常数**学习率鲜少最优，因为理想步长在训练中*变化*：早期想要**大步**快速穿越损失曲面，但接近极小值时大步会**过冲振荡**，于是想**缩小**。过高发散；过低爬行。调度随时间改变 LR，兼得两者之长。

**常见调度：**
- **阶梯衰减**——每 N epoch 降一个因子（如 10×）。简单有效。
- **指数衰减**——平滑连续下降。
- **余弦退火**——沿余弦曲线降至（近）零；很流行的现代默认，在高低速率上都花时间。
- **带温重启的余弦（SGDR）**——周期性把 LR 跳回以逃离尖锐极小并探索。
- **平台减小**——仅当验证损失停滞时降 LR；不预知合适调度时鲁棒。
- **One-cycle（Smith）**——单次运行内先升后降 LR，常训练更快（超收敛）。

**Transformer 标准是线性 warmup + 衰减：** 前约 1–10% 步线性**升到**峰值，然后**余弦或线性衰减**下降。**Warmup** 重要是因为自适应优化器（Adam）早期尚未建立可靠方差估计——在噪声统计上迈一大步会破坏稳定甚至炸掉训练，所以要缓入。

挑**峰值** LR 用**学习率查找器**：在几百次迭代内扫升 LR 并画损失-LR 曲线；选损失开始发散前一点的值。实践中**调度可让最终准确率波动数个百分点**——常比选哪个优化器更重要。

**要点：**
- Warmup + 余弦是 Transformer 默认。
- LR 查找器廉价挑出好峰值。
- 平台减小对未知场景鲁棒。
- 调度选择常比优化器选择更重要。

### 42. 排查 RAG/LLM 应用的回答质量问题

**频率：** 中

**题目：** 你的 RAG 聊天机器人在生产环境给出错误、含糊或幻觉的答案。请说明你会如何系统性地定位并修复。

**答案：** 最常见的错误是上来就随机换模型或改 prompt。一次 RAG 回答会流经三个阶段——**retrieval → context assembly → generation**——任何一个阶段都可能出问题。整件事的关键在于：在动手之前先 **定位是哪个阶段失败**。

**第一步，让失败可观测。** 为每次查询记录完整 trace：改写后的 query、带分数的检索 chunks、拼装出的精确 prompt、最终答案。攒一个小 **eval set**（30~100 个真实失败问题及期望答案）。无法复现就无法调试。

**阶段一 —— Retrieval（最常见元凶）。** 对一个失败查询，看检索到的 chunks：*答案到底在不在里面？* 如果正确文档根本没被检索出来，生成阶段毫无机会。对照已知相关文档检查 **recall@k**。常见修法，大致按收益排序：
- *Chunking* —— 块太大稀释相关性，太小丢失上下文；调块大小与 overlap。
- *Embeddings / query 失配* —— 换更好的 embedding 模型，或用 **hybrid search**（BM25 + 向量）来兜住语义漏掉的关键词/缩写查询。
- *Reranking* —— 对 top-50 用 cross-encoder 重排，能显著锐化 top-5。
- *Metadata filtering* —— 排除混入的错误租户/日期/版本 chunk。

**阶段二 —— Context assembly。** 正确 chunk 被检索到了，答案却仍然差。确认该 chunk **确实进入了 prompt**（token 预算截断是经典的隐形 bug）。检查 **排序**：模型有"lost in the middle"问题，应把最相关 chunk 放开头或结尾，而不是埋在中间。检查是否有矛盾或重复 chunk 干扰模型。

**阶段三 —— Generation。** context 正确且完整，模型却仍幻觉或无视它。测量 **faithfulness**（答案是否忠于所给 context）与 **answer relevance**。修法：更强的指令要求"只依据 context 作答，否则说不知道"、降低 temperature，或换更大的模型。

**用对工具。** **RAGAS** 或 **TruLens** 能在你的 eval set 上自动打分 faithfulness、context precision/recall、answer relevance——用量化代替肉眼判断哪个阶段最弱。

**一次只改一个变量。** 把它当实验：每次改动都在 eval set 上做 A/B，只保留能推动指标的改动。按出现频率排序，根因通常是：(1) 检索没命中，(2) 分块太粗，(3) context 被截断/排序错误，(4) prompt 没强制 grounding，(5) 模型太弱。

**要点：**
- 动手前先定位失败阶段——retrieval / assembly / generation。
- retrieval 是最常见元凶：查 recall@k、chunking、hybrid search、reranking。
- 确认 context 真的进了 prompt，并排好序以避免"lost in the middle"。
- 用 RAGAS/TruLens + 固定 eval set；一次只 A/B 一个变量。

### 43. 离线指标好、线上却差的排查

**频率：** 高

**题目：** 你的模型离线跑分很漂亮——比如 held-out 集上 AUC 0.92——可一上线，实际表现明显变差。你如何诊断并修复这个离线-线上差距？

**答案：** 这是最常见的高级别翻车之一，有一份标准的嫌疑清单。按可能性从高到低排查。

**1. 数据泄漏（头号嫌疑）。** 当离线指标*好得可疑*时，先假定存在泄漏，直到被证伪。某个特征编码了目标（比如一个在事件*之后*才填充的字段，或与标签强相关的 ID），线上根本无法复现。**诊断：** 按重要性对头部特征做 ablation——如果单个特征扛起了整个模型，它多半在泄漏。逐一核查每个特征在*预测时刻*的真实可得性。

**2. 训练/服务偏斜（train/serving skew）。** 特征在离线管线里用一种方式算（batch SQL、全窗口聚合），线上却用另一种方式算（流式、部分窗口、缺失值默认值不同）。模型看到了它从未训练过的分布。**诊断：** 记录线上真实的特征向量并在离线重新打分，与同一实体的离线向量对比。**修复：** 用共享的 **feature store** / 训练与服务共用同一套特征变换代码。

**3. 划分方式错误。** 对时序或分组数据做随机划分，会通过**时间泄漏**（用未来预测过去）或**分组泄漏**（同一用户同时出现在训练与测试）虚高离线分。**修复：** 按时间划分；分组感知划分，让同一实体只落在一个 fold。

**4. 分布漂移。** 线上流量与训练窗口不同——新用户、季节性、UI 改动、营销活动。**诊断：** 对比训练与线上的特征分布（PSI/KL）；持续监控 drift。

**5. 指标/标签不匹配。** 你的离线指标（AUC、logloss）并非业务真正关心的（营收、留存、服务阈值下的 CTR）。模型可以在 AUC 上取胜，却在用户实际看到的 top-k 上落败。**修复：** 让离线指标对齐线上决策，并在真实工作阈值处评估。

**6. 反馈回路与服务约束。** 上线的模型会改变它日后看到的数据（推荐结果会偏置未来的点击），或延迟预算迫使用更小/量化的模型或近似检索，而离线评估从未建模这些。

**实操顺序：** 先确认划分是诚实的 → 查泄漏 → 把线上特征离线回放以抓偏斜 → 对比分布 → 核实指标映射到业务目标。最终务必用小规模**线上 A/B 测试**验证，而不是只信离线数字。

**要点：**
- 离线分好得可疑通常意味着泄漏或划分泄漏——先查这两项。
- 训练/服务偏斜是最常见的沉默差距；共享 feature store 是解法。
- 用能镜像生产运行方式的时间感知、分组感知划分。
- 离线指标必须在真实阈值处映射到业务决策；并用 A/B 测试确认。

### 44. 设计推荐/排序系统的机器学习部分

**频率：** 高

**题目：** 请设计一个大规模推荐系统的机器学习部分（例如视频信息流或电商首页），要求在约 100ms 内从数千万候选中选出少量物品。请讲清楚整体架构、模型选型、训练数据以及如何衡量效果。

**答案：** 业界标准答案是**多阶段漏斗（multi-stage funnel）**，因为不可能对每个请求都给 5000 万物品打分。每一阶段用 recall 换 precision，单个物品的计算成本逐级升高。

**第一阶段 —— 候选生成 / 召回（candidate generation / retrieval）。** 用低成本方式把语料从数千万裁到几百/几千。主力是 **two-tower 模型**：user tower 和 item tower 分别产出 embedding，训练目标是让相关对的点积更高。item embedding 离线预计算并建入 **ANN** 索引（FAISS、ScaNN、HNSW），召回就变成毫秒级的最近邻查找。实践中并行跑多路召回 —— two-tower、最近/热门、collaborative filtering、"看过 X 的人"、graph-based —— 再对候选取并集。这种多路融合往往比单个花哨召回器更重要。

**第二阶段 —— 排序（ranking）。** 用重模型对这几百个候选打分，依赖**丰富特征**：user 特征（历史、画像、embedding）、item 特征（类目、上架时长、热度、creator embedding），以及关键的**交叉/上下文特征**（时段、设备、query、user-item 交互次数）。gradient-boosted trees（LightGBM/XGBoost）是很强的 baseline；大厂用**深度排序模型**（Wide&Deep、DeepFM、DLRM）自动学特征交叉。通常是**多目标（multi-objective）**：同时预测 CTR、watch-time、点赞、完播，再用加权或学习得到的公式融合。

**第三阶段 —— 重排（re-ranking）。** 最终策略层：保证**多样性（diversity）**（MMR / 避免同一 creator 连出 5 条）、注入**新鲜度/探索（exploration）**、执行业务规则（广告、运营位、去重）并混排。产品判断都体现在这一层。

**训练数据与标签。** 用**隐式反馈（implicit feedback）**（点击、观看、购买），因为显式评分太稀疏。两个大坑：**position bias**（头部物品被点是因为位置靠前 —— 用 inverse-propensity weighting 纠偏，或在特征里放位置、serving 时置零）和召回的 **negative sampling**（对未曝光物品采样，in-batch negatives 是标配）。

**评估。** 离线：排序看 **AUC / logloss**，召回看 **recall@k / NDCG** —— 必要但与线上真实效果相关性弱。真正的裁判是**线上 A/B test**（看 engagement/收入及护栏指标）。要警惕**反馈闭环（feedback loop）**：模型推热门 → 热门拿到更多数据 → 更被推荐，需靠 exploration 和 popularity 去偏来对抗。

**serving。** item embedding 与 ANN 索引离线预计算；user tower embedding 与排序实时计算，卡在严格的 latency budget 内。**冷启动（cold start）**用内容特征与热度兜底处理新用户/新物品。

**要点：**
- 多阶段漏斗（retrieval → ranking → re-ranking）是为满足 latency budget，每阶段用 recall 换 precision。
- two-tower + ANN 做低成本高召回检索；GBDT 或深度模型配丰富交叉特征做精排。
- 用 implicit feedback 训练，显式处理 position bias 与 negative sampling。
- 离线指标（AUC/NDCG/recall@k）只做筛选，线上 A/B 看 engagement 才是定论；同时警惕热度反馈闭环与冷启动。

### 45. ResNet、EfficientNet、ViT

**频率：** 中

**题目：** 请比较 ResNet、EfficientNet 和 ViT 三类视觉架构。各自何时是正确默认？

**答案：** 这三者标志图像建模的主要时代。

**ResNet** 使**深度可训练**。其**残差连接**（`y = F(x) + x`）给梯度直接通路，使 50/101/152 层 CNN 能真正优化。它成为分类、检测、分割的**事实上主干**，并仍是**强而可靠的默认**——尤其在**较小数据集**上，其卷积先验（局部性、权重共享）是优势。

**EfficientNet** 优化**每 FLOP 的准确率**权衡。不是缩放单一维度，而是用**神经架构搜索（NAS）**设计好基网，再施**复合缩放**——以平衡比例**同时增加深度、宽度和输入分辨率**，优于缩放任一单轴。它由 **MBConv**（倒置残差）块和 **squeeze-and-excitation（SE）**通道注意力构成，在**算力/内存预算**受限时极佳。

**ViT（Vision Transformer）**完全舍弃卷积：把**图像切成 patch**，每个线性嵌入为 token，送入**标准 Transformer**。内置先验弱，因而**吃数据**——需**大规模预训练**（JFT-300M）才能胜 CNN——但随后**缩放优雅**，从第一层就捕捉全局关系。

**ConvNeXt 等混合体**把 Transformer 时代设计技巧（大核、LayerNorm、GELU、更少激活）带回纯 CNN，用卷积效率匹配 ViT 准确率。

**经验法则：** **小到中**数据与追求效率时用 ResNet/ConvNeXt；有**规模**（海量数据或强预训练检查点）时用 **ViT 及后继（Swin、DINOv2）**。

**要点：**
- ResNet：残差实现深网。
- EfficientNet：NAS + 复合缩放。
- ViT：patch + Transformer；需规模。
- ConvNeXt：现代化 CNN，与 ViT 竞争。

### 46. 端到端设计欺诈/异常检测系统

**频率：** 中

**题目：** 请为支付平台端到端设计一个欺诈检测系统。它要实时给交易打分，要应对只有约 0.1% 是欺诈的现实，还要跟上不断变换手法的欺诈者。你会怎么建？

**答案：** 欺诈检测由三个硬约束定义：**极端类别不平衡（class imbalance）**、**标签延迟/带噪**、**会自适应的对手（adversary）**。所有设计取舍都源于这三点。

**数据与标签。** 欺诈常占交易 <0.1%，且标签来得晚 —— chargeback 可能几周后才确认，所以近期的"正常"交易其实是*未标注*的。处理不平衡用 class weights 或 focal loss，而非朴素过采样；SMOTE 在真实表格欺诈上很少奏效。应对标签延迟，就在足够"成熟"的时间窗上训练。

**特征才是胜负手。** 信号藏在 **velocity / aggregation 特征**里：每卡每小时交易数、金额相对用户 30 天均值、近一天的不同商户/设备数。再加**行为/设备（behavioral/device）**信号（device fingerprint、IP、打字/会话行为）与 **graph 特征**（共用设备的卡、共用收货地址、账户团伙）—— 欺诈本质是关系型的。

**两阶段架构。** 第一阶段：**低成本、高召回的过滤器**（简单 rules + 轻量模型），几毫秒内放行约 99% 明显正常的流量。第二阶段：**精准模型**（gradient boosting —— XGBoost/LightGBM —— 是主力）加一个 **rules engine** 覆盖已知模式和硬性合规约束。rules 与 ML 并存：rules 对已知欺诈给出即时、可解释的覆盖，ML 兜住其余。

**阈值是业务决策。** 别优化 accuracy（预测"从不欺诈"就有 99.9%）。用 **PR-AUC**，并从**代价矩阵（cost matrix）**选工作阈值：误拦正常客户（false positive）有实打实的收入/体验成本，漏过欺诈（false negative）是直接损失。通常输出分数区间 → 自动通过 / 自动拒绝 / **转人工审核**。

**human-in-the-loop。** case-management 队列让分析师复核边界样本，他们的结论成为新鲜标签，闭合回路。队列按 分数 × 金额 排优先级。

**对抗性漂移。** 欺诈者不断试探、适应，**concept drift** 是常态 —— 频繁重训（每天/每周），监控分数分布与固定阈值下的 precision，漂移即告警。给监督模型搭配**无监督异常检测（unsupervised anomaly detection）**（isolation forest、autoencoder）来发现监督模型从没见过的*新型*欺诈。

**可解释性与 serving。** 分析师和监管都要理由，故对每条告警用 SHAP / reason codes。部署在低延迟 feature store 后面，保证 aggregation 特征在训练与实时打分间一致，避免 train/serve skew。

**要点：**
- 设计由极端不平衡、标签延迟/带噪、自适应对手驱动，而非靠挑花哨模型。
- velocity/aggregation、行为/设备、graph 特征承载信号；feature store 保证训练与线上一致。
- 两阶段（低成本高召回过滤 → 精准模型 + rules engine）满足延迟；监督 + 无监督兼顾新型欺诈。
- 用 cost matrix / PR-AUC 调阈值，边界样本转人工，频繁重训并配 drift 监控与 SHAP 解释。

### 47. 控制 LLM 应用的成本与延迟

**频率：** 高

**题目：** 你的 LLM 功能能跑，但规模化后又慢又贵。你会拉哪些杠杆？如何决定优先级？

**答案：** 先**度量再优化**。跟踪每次请求的 cost、输入/输出 token 数，以及 p50/p95/p99 的 latency（长尾对体验和 SLO 很关键）。把两类问题分开——p99 慢和账单高是不同的问题——并把成本归因到 input 还是 output token，因为 output 通常贵得多。

**模型分层 / 路由（routing）** 是最大的杠杆。简单查询走小而便宜的模型，只有难的才升级到 frontier 模型——用一个分类器或置信度判断来选层。仅此一项常能把成本降 5-10 倍，因为大部分流量都很简单。为常见路径蒸馏一个小的专用模型能更进一步。

**压缩 token。** 输出长度上限（`max_tokens`）和"简洁作答"的指令直接削减昂贵的一侧。精简 prompt 和 few-shot 例子；用 RAG 只注入相关片段，而不是把整篇文档塞进 context。更少的 input token = 更低 cost **且**更低 latency。

**缓存。** Prompt caching（跨调用复用静态 system prompt / 长 context）能显著降低 cost 和 time-to-first-token，尤其是重复前缀。Semantic caching 把近似重复查询的答案缓存起来（对 query 做 embedding，命中就返回缓存响应），非常适合 FAQ 型流量。

**感知延迟 vs 实际延迟。** 流式（streaming）输出让用户感受到的是 time-to-first-token，即使总生成时间没变——便宜且对体验提升巨大。

**服务端效率（自托管）。** 用 vLLM 这类优化服务器做 continuous batching 和 PagedAttention（KV-cache 更高效）；对权重做量化（INT8/FP8/4-bit）以在单卡上跑更多吞吐；可考虑 speculative decoding 加速生成。Batching 提高吞吐，代价是单请求 latency 略增。

**权衡与 SLO。** 每个杠杆都在和质量做权衡：更小的模型、激进裁剪和量化都可能降低答案质量，所以要用 eval 集把关。设定明确 SLO（如 p95 < 2s，cost < $X / 1k 请求），朝目标优化而不是一味追求归零。常见陷阱：只优化平均值而 p99 用户流失；在需要时效的场景缓存了过期答案；过度量化导致质量悄悄下降。

实战顺序：先限制输出、精简 prompt（免费）→ 加缓存 → 加路由/分层 → 自托管再投入服务端级优化。

**要点：**
- 先度量：cost/请求、token、p50/p95/p99——output token 主导成本。
- 模型分层/路由（小模型 + 升级）通常收益最大。
- 压 token（max_tokens、RAG、精简 prompt）并缓存（prompt + semantic）。
- 用 streaming 改善感知延迟；自托管用 vLLM/量化/speculative decoding 提吞吐；每次改动都用质量和 SLO 把关。

### 48. 多头注意力

**频率：** 中

**题目：** 请解释多头注意力以及 MQA/GQA 效率变体。

**答案：** 不是在完整 `d_model` 维上算一次注意力，多头注意力把 **Q、K、V 投影到 `h` 个低维子空间**（头），在**每个子空间独立**跑缩放点积注意力，再**拼接**结果并投回 `d_model`。总参数与同宽度的单头相当，但表达力更高。

**为何多头有帮助：** 每个头能**同时在不同子空间关注不同模式**——一头追句法依赖，一头共指，一头局部位置，一头语义相似。单头则不得不把这些角色平均为一个注意力分布；拆开让模型一次捕捉多个关系。（头数通常为 `d_model / 64`。）

**它们造成的推理瓶颈：** 自回归生成时你**缓存所有过去 token 的 key 和 value**（**KV 缓存**）。头多且上下文长时，这个缓存成为主要内存成本和带宽瓶颈。两变体缩小它：
- **多查询注意力（MQA）**——保留独立 query 头但让**所有头共享单一 K/V**。大幅削减 KV 缓存，以少量质量为代价。
- **分组查询注意力（GQA）**——**折中**：把头分为几个**组**，每组共享一个 K/V。恢复 MQA 大部分内存节省且质量接近满额，所以 **LLaMA-2/3 和 Mistral** 用它。

进一步观察：**许多头冗余**——研究表明很大一部分可在训练后**剪枝**，准确率损失很小。

**要点：**
- 不同子空间的并行头。
- 头常可解释地专精。
- MQA/GQA 减少长上下文推理的 KV 缓存。
- 剪枝显示许多头冗余。

### 49. 位置编码：正弦、学习、RoPE、ALiBi

**频率：** 中

**题目：** 为何注意力需要位置编码？请比较正弦、学习、RoPE 和 ALiBi。

**答案：** 注意力对**置换不变**——打乱 token 顺序不改变输出，因为它只看内容不看位置。但语言中顺序至关重要（"狗咬人"≠"人咬狗"），所以必须显式注入位置信息。

**正弦（原始 Transformer）**——加不同频率的固定正弦向量。无参数，可外推到更长序列（虽不完美）。

**学习嵌入（BERT/GPT-2）**——每个位置一个可学向量，效果相当，但**不能超出训练长度泛化**——未见位置无嵌入。

**RoPE（旋转位置嵌入）**——按**位置相关角度旋转 Q 和 K**，**乘性**地编码相对位置。泛化更好，是 **LLaMA、Mistral、Qwen** 的标配。

**ALiBi**——在注意力分上加**位置相关线性偏置**（距离越远惩罚越大），不需嵌入，**外推良好**。

**NoPE**——在某些仅解码器设置中完全去位置编码（因果掩码本身提供顺序）。

**长上下文扩展：** 带缩放/插值（**NTK-aware、YaRN**）的 RoPE 把预训练模型**拉伸**到比训练时更长的长度工作，无需从头重训。

**要点：**
- 注意力需要显式位置信号。
- RoPE 主宰现代 LLM。
- ALiBi 对更长序列外推良好。
- YaRN/NTK 缩放将 RoPE 拉伸到长上下文。

### 50. BERT vs GPT vs T5

**频率：** 中

**题目：** 请比较 BERT、GPT、T5。仅解码器模型为何赢得缩放竞赛？

**答案：** 三者代表 **Transformer 的三种拓扑**，各配一个预训练目标：

- **BERT——仅编码器、双向。** 用**掩码语言建模**（用*两侧*上下文预测随机隐藏的 token）加下一句预测预训练。因为一次看到完整上下文，它构建丰富的**理解**表示——微调用于分类、NER、抽取式 QA。它**不为生成设计**。
- **GPT——仅解码器、自回归。** 用**因果掩码**（每 token 只看过去）做**下一 token 预测**预训练。生成原生，此目标可扩展成通用助手。
- **T5——编解码器、文本到文本。** 把**每个任务都写成 text→text**（"translate: ..."、"summarize: ..."），通过掩码并重建跨度预训练。跨翻译、摘要、分类即生成都灵活。

**仅解码器为何在规模上胜出：** 原始文本上单一的**下一 token 目标**是最易扩展到万亿 token 的东西，并解锁了**上下文学习**——**无需微调**就能从提示中的示例学任务。这种涌现的灵活性加上训练效率，正是几乎所有前沿基础模型（GPT-4、Claude、LLaMA、Mistral）都是仅解码器的原因。

**但其他各守其位：** **BERT 家族仍主宰廉价、高吞吐的分类与嵌入**，那里低成本的双向理解胜过庞大的生成模型。**编解码器**模型（T5、BART、FLAN-T5）在中等规模的**微调 seq2seq** 任务（如翻译）上仍强。

**要点：**
- BERT = 理解；GPT = 生成；T5 = 两者。
- 仅解码器赢得缩放竞赛。
- BERT 家族仍主宰廉价分类/嵌入。
- T5 在文本到文本任务微调中流行。

### 51. GAN

**频率：** 中

**题目：** GAN 如何工作？它们有哪些经典失败模式？

**答案：** GAN 让两个网络在**极小极大博弈**中对抗。**生成器 `G`** 把随机噪声 `z` 映射为合成数据；**判别器 `D`** 试图区分真样本与生成样本。它们对抗训练：`D` 最大化识假准确率，`G` 通过产出足以骗过 `D` 的样本来最小化它——梯度*穿过* `D` 学习。理论均衡时，`G` 重现真实数据分布，`D` 只能瞎猜。

**实践中出了名的难训：**
- **Mode collapse**——`G` 发现几个能可靠骗过 `D` 的输出就只产这些，**忽略分布的大片区域**（如反复生成同一张脸）。
- **训练不稳定**——两网必须保持**平衡**；`D` 太强则 `G` 梯度消失；振荡和发散常见。
- **无原则似然**——无法直接衡量 `G` 拟合数据的程度，评估和选型别扭。
- **超参脆弱**——结果随架构和学习率剧烈波动。

**主要变体**应对这些：**DCGAN**（稳定的 CNN 主干）、**WGAN/WGAN-GP**（Earth-Mover 距离，训练远更稳）、**StyleGAN**（基于风格的生成器，长期是逼真人脸的 SOTA）、**条件 GAN**（类或文本引导）、**CycleGAN**（无配对图到图翻译）。

**扩散为何取代它们（2022 起）：** 扩散用简单回归损失稳定训练，给出**更好的分布覆盖**和多样性，避免 mode collapse。GAN 保留一个优势——**单次前向推理**，所以采样远比迭代扩散**快**。

**要点：**
- 对抗 min-max 博弈。
- Mode collapse 与不稳定是经典失败。
- StyleGAN 家族长期保持人脸 SOTA。
- 2022 起扩散基本取代 GAN。

### 52. 构建可靠的 LLM 结构化信息抽取管道

**频率：** 中

**题目：** 你需要把大量非结构化文档（发票、简历、合同）批量转成干净的结构化 JSON 记录，供下游系统消费。如何设计一个足够可靠的 LLM 抽取管道？

**答案：** 核心难点在于：裸提示词只会返回看起来合理的文本，而不是保证合法的记录。要把 LLM 当成 ETL 管道中的一个环节，外面包上校验、重试与监控，而不是把它当成完整方案。

**从 schema 出发，而非从 prompt 出发。** 用显式的类型化 schema（Pydantic model 或 JSON Schema）定义目标：字段名、类型、枚举、必填/可选、格式（ISO 日期、货币代码）。schema 是所有环节强制执行的契约。把它放进 prompt 让模型知道输出形状，再用它做校验。

**约束输出，而不是祈祷。** 优先使用 **function/tool calling** 或厂商的 strict/JSON 模式，让模型直接产出符合 schema 的 JSON。**Instructor**（基于 Pydantic）或 **Outlines**（受语法约束的解码）之类的库能让非法 JSON 在结构上不可能出现，而不只是"不鼓励"。这在源头消除了一整类解析错误。

**先校验，再重试。** 每个响应都对照 schema 解析并校验。失败时执行有上限的 **retry-on-error 循环**（2~3 次），把校验错误回灌到 prompt（"字段 `amount` 必须是数字，你返回的是 '$1,200'"）。多数瞬时错误在第二次就能自愈。超过 N 次则送入死信队列（dead-letter queue）。

**处理长文档。** 40 页的合同无法干净地塞进 context 或注意力窗口。先 **chunk 分块**，逐块抽取，再 **merge 合并**（map-reduce）：调和重复项，每个字段取置信度最高的值，并保留 provenance（字段来自哪一块/哪一页）以便审计。

**对抗幻觉字段与缺失字段。** 指示模型在不确定时输出 `null` 而非猜测，并要求给出每字段的 **confidence** 或来自原文的支撑引用/span。没有 grounding span 的字段一律视为可疑。

**按置信度引入 human-in-the-loop。** 高置信记录自动通过；低置信（或低于校验阈值）的记录送入人工审核 UI。这样无需人工过目每一条记录，也能拿到很高的整体准确率。

**在后处理中做归一化。** 用确定性代码（而非 LLM）来规范日期、货币、电话号并去重。让 LLM 的职责保持窄。

**做字段级评测。** 建一个带标注的 gold set，测量 **每字段的 precision/recall/F1**，而不是笼统的"看起来对"。这能告诉你该修哪个字段，并为 prompt/模型变更设卡。

**控制成本。** 默认跑便宜的小模型，只把校验失败或低于置信阈值的记录 **escalate 升级** 给更强的模型。

**要点：**
- schema 即契约：用受约束解码 + 校验，而非解析自由文本。
- 有上限的重试循环把校验错误回灌，能修复多数失败。
- 长文档用 chunk-extract-merge；按置信度分流到人工审核。
- 在 gold set 上做字段级 precision/recall；便宜模型优先、失败再升级以控成本。

### 53. 扩散模型

**频率：** 中

**题目：** 扩散模型如何工作？它们为何超越了 GAN？

**答案：** 扩散模型通过**学习逆转逐步加噪过程**来生成数据。

**前向过程**（固定、无学习）：取一张真实图像，在 `T` 步中反复加少量**高斯噪声**直到变成**纯噪声**。这定义了从干净数据到噪声的序列。

**反向过程**（学习）：训练一个网络——历史上是 **U-Net**，如今常是 **DiT**（扩散 Transformer）——**预测每步加的噪声**。生成时从随机噪声起**迭代去噪**：预测噪声、减去一点、重复，从噪声倒走到干净样本。

**训练极其简单：** 取随机图像、随机时间步、加对应噪声，用普通 **MSE 损失**训练网络预测该噪声（Ho 等，DDPM）。无对抗博弈，正因如此**稳定**。

**让它实用：**
- **更快采样**——朴素采样需数百步；**DDIM、DPM-Solver** 削减到 10–50 步。
- **潜空间扩散（Stable Diffusion）**——在 **VAE 紧凑潜空间**而非像素上跑整个过程，约 10× 提速，使高分辨率生成可行。
- **classifier-free guidance**——条件生成时联合训练**有与无**条件（如文本）的模型，采样时把预测推向有条件、远离无条件，按 **guidance 权重 `w`** 缩放。`w` 越大 = 提示遵循越强（以一定多样性为代价）。

**扩散为何击败 GAN（2022 起）：** 训练远更**稳定**（无 mode collapse 或判别器平衡）且**分布覆盖/多样性更好**。GAN 仍在**推理速度**上胜出——单次前向 vs 多步去噪。扩散现为图像、视频、音频合成的主导范式（DALL-E 3、SD3、Midjourney、Sora 风视频）。

**要点：**
- 学去噪；迭代反向过程。
- 潜空间扩散让高分辨率实用。
- Classifier-free guidance 做条件化。
- 替代 GAN 成为 SOTA 生成范式。

### 54. 自监督学习

**频率：** 中

**题目：** 什么是自监督学习？它为何解锁了基础模型？

**答案：** 自监督学习（SSL）**从无标签数据里发明监督**。无需人工标注，你定义一个**前置任务**，答案本就在数据中——遮住输入的一部分，训练模型去预测它。这解锁了从**海量、廉价、无标签语料**（全网文本、数十亿图像）学习，正是基础模型得以成立的全部原因：标注数据稀缺昂贵，而原始数据近乎无限。

**经典前置任务：**
- **掩码语言建模**（BERT）——隐藏 token，用双向上下文预测。
- **下一 token 预测**（GPT）——预测下一个 token；每个 LLM 背后的目标。
- **掩码图像建模**（MAE）——遮住图像 patch，重建它们。
- **对比学习**（SimCLR、CLIP）——把同一物体两种增强（或图像与其标题）的表示拉**近**，把不同物体推**远**。
- **bootstrap 方法**（BYOL、DINO）——无负样本，靠在线网络匹配缓慢更新的目标网络学习。

**为何强大：** 这样学到的表示是**通用**的。之后你把它**迁移**到下游任务，要么**微调**整个模型，要么**线性探测**（冻结主干、训练小头）——常只需少量标注数据就达强性能。这套**先预训练再适配**范式如今主宰 NLP 与视觉。

**一个关键细节：** **前置任务的设计很重要**——尤其在较小规模下，精心选的前置任务给出的表示胜过单纯把模型做大。前置任务必须迫使模型真正学到数据结构中有用的东西，而非学到捷径。

**要点：**
- 从数据自身发明监督。
- 驱动 BERT、GPT、CLIP、DINO、MAE。
- 预训练 + 微调是现代工作流。
- 前置任务设计重要。

### 55. 知识蒸馏

**频率：** 中

**题目：** 请讲解知识蒸馏。蒸馏出的学生为何能胜过从头训练？

**答案：** 知识蒸馏训练一个小**学生**模型去**模仿更大的教师**模型，把教师学到的行为转移进更廉价的包装里。

**核心思想是软标签。** 硬标签只说"这张图是猫"。教师的**完整输出分布**说"90% 猫、7% 狗、0.5% 狐狸……"——这些小概率编码了**暗知识**：教师已学到猫更像狗而非汽车。学生从这丰富信号中学到的远多于单一 one-hot 标签。损失结合：
- 对真标签的**硬标签交叉熵**，与
- 对教师输出分布的**软标签 KL 散度**。

**温度** `T` 控制它：softmax 前把 logits 除以 `T > 1` 会**软化**分布，放大信息量大的小概率，让学生看到教师完整的相似性结构。

**变体**超越输出：**隐状态匹配**（对齐中间表示）、**注意力匹配**（对齐注意力图）、生成任务的**序列级蒸馏**。

**典型应用：** 把 BERT 压缩为 **DistilBERT / TinyBERT / MiniLM**；靠蒸馏**前沿 LLM 输出**造出能干的开源模型（Alpaca、Vicuna 在 GPT 生成数据上训练）；生产端上模型。

**学生为何能胜过从头训练：** 教师**更平滑、信息更丰的标签分布**是比稀疏硬标签更易的优化目标——它正则化并引导学生走向更好的极小点。它还与量化、剪枝**叠加良好**做到最大压缩。一个实用注意：蒸馏时**迁移数据的多样性比纯粹的数量更重要**——你需要能揭示教师在整个空间中行为的输入。

**要点：**
- 匹配教师软输出，不仅硬标签。
- 温度软化概率以获更丰监督。
- DistilBERT、Vicuna 是经典示例。
- 与量化叠加获最大压缩。

### 56. 量化：INT8、INT4、GPTQ、AWQ

**频率：** 中

**题目：** 请解释 LLM 推理的量化及主要方法（INT8、INT4、GPTQ、AWQ）。

**答案：** 量化用**比常规 FP16/FP32 更少的位**存储权重（有时含激活）。回报有二：**内存**——INT4 模型比 FP16 小约 4×，原需多卡的模型能塞进单卡；以及**速度**，因为流经内存带宽瓶颈（LLM 推理的主导因素）的数据更少。

**精度权衡：**
- **INT8**——配一遍**校准**找好缩放因子，INT8 训练后量化对多数模型**近乎无损**。安全默认。
- **INT4**——省得多但需**更谨慎**；朴素取整会掉可察觉的准确率，正因如此才有下面的聪明方法。

**主要方法：**
- **GPTQ**——训练后，逐层用**二阶（Hessian）信息**最小化每层输出的重建误差。4-bit 下准确。
- **AWQ（激活感知权重量化）**——观察到**一小部分权重通道显著**（它们与大激活交互）并保护之，其余激进量化。快且准。
- **bitsandbytes NF4**——为权重近高斯分布调优的 4-bit "normal float" 格式；是 **QLoRA** 用的基模格式。
- **GGUF / llama.cpp**——本地高效 CPU/GPU 推理量化模型的文件格式与内核。

**量化感知训练（QAT）**更进一步，在**训练中**模拟量化让模型学会对其鲁棒——质量最好，但因需（重）训练而昂贵。

**实用服务注意：** 开源 LLM 常在 **INT4–INT8** 服务且损失极小；但**小模型在 INT4 下退化更多**，对高要求任务（推理、代码）保持更高精度。长上下文还要**量化 KV 缓存**——大序列长度时它可主导内存。

**要点：**
- INT8 几乎免费；INT4 需谨慎。
- GPTQ 与 AWQ 是顶级训练后方法。
- QLoRA 用 NF4 基 + FP16 LoRA。
- 长上下文也量化 KV 缓存。

### 57. 分词：BPE、WordPiece、SentencePiece

**频率：** 中

**题目：** 请比较 BPE、WordPiece、SentencePiece。分词为何引发 LLM bug？

**答案：** 分词把原始文本切成模型实际处理的离散单元（**token**）——通常是**子词**，介于字符（token 太多）与整词（词表巨大、无法处理未见词）之间的折中。下面的方案都是从语料学词表的**子词**方法。

**三种方案：**
- **字节对编码（BPE）**——从单字符起，**贪心地反复合并最频繁的相邻对**，直到达到目标词表大小。高频词成单 token，罕见词拆成片。**GPT 家族与 RoBERTa** 使用。
- **WordPiece**——类似合并，但不按原始频率，而是合并在语言模型下最能**提升训练语料似然**的对。**BERT** 使用。
- **SentencePiece**——本身不算合并算法，而是**直接在含空格的原始文本上**操作的框架（把空格编码成特殊符号），因此**无需语言相关的预分词**，也能处理无空格语言（中文、日文）。可跑 BPE 或 unigram-LM 分词；**T5、LLaMA、Mistral** 使用。

**字节级 BPE**（GPT-2 起）在**原始字节**而非 Unicode 字符上操作，能表示**任意**输入——emoji、罕见脚本、任意符号——无 OOV 失败。

**词表大小权衡：** **更大**词表（典型 32k–256k）意味着**更短**的 token 序列（注意力更省、每上下文窗口容纳更多文本），但**嵌入表与 softmax 更大**。小词表则相反。

**分词为何引发真实 bug：** 模型只看到 token，所以文本切分方式的怪癖会渗入行为。**数字**可能切分不一致（"1234" 是一个 token 而 "1235" 是两个），这正是 LLM 不擅算术的原因——现代模型加**逐位**拆分帮忙。**代码**的空格/缩进分词别扭，**非英语**文本每词可能耗多得多的 token（更贵且降质），除非词表训练成多语。著名失败（"SolidGoldMagikarp" 故障 token）直接源于分词伪影。

**要点：**
- BPE：贪心基于频率的合并。
- SentencePiece：语言无关、原始文本。
- 字节级 BPE 处理任意输入。
- 词表大小权衡序列长度与嵌入大小。

### 58. 生产选型：开源自托管 vs 闭源 API

**频率：** 中

**题目：** 一个新的生产功能，你如何在闭源 frontier API（OpenAI/Anthropic/Google）和开源自托管模型（Llama/Mistral/Qwen）之间做决策？

**答案：** 把它当作跨几个维度的组合决策，而不是信仰之争。

**数据隐私与合规。** 如果数据不能离开你的环境——受监管的医疗/金融、air-gapped/on-prem 部署——这往往直接决定选开源自托管，与其他因素无关。API 提供数据处理协议和 zero-retention 模式，但只有自托管才能保证数据永不越界。

**规模化成本。** API 是按 token 付费：固定成本近乎为零，非常适合低量或波动流量。自托管是固定的 GPU 账单（租或买），靠摊销回本。这里有一个**交叉点（crossover）量**：低于它 API 更便宜，高于它自托管更划算。交叉点取决于模型大小和利用率——小开源模型在高利用率 GPU 上，一旦达到持续高吞吐就能打败 API 报价；而闲置的集群纯属浪费。经验法则：只有能让 GPU 一直忙起来时才自托管。

**能力上限。** 闭源 frontier 模型在最难的推理、long-context 和多模态任务上仍然领先。如果功能需要顶级能力，今天 API 可能是唯一能过线的选择。

**定制与控制。** 开源模型给你完全自由：随意 fine-tune/LoRA、锁定精确版本（不会有悄悄升级搞坏 prompt）、调优 serving 栈、不受 rate limit 约束。API 只能用它提供的 fine-tuning 选项和配额，还可能在你脚下弃用模型。

**运维负担与锁定。** 自托管意味着你要负责 GPU 供给、serving（vLLM）、扩缩容、可用性和升级——需要真实人力。API 把这些全外包，但带来 vendor lock-in，以及对其可用性和定价的依赖。

**实战建议。** 先用 API 快速验证产品——无需基建、模型最好、低量时便宜。当你摸清真实流量和需求后，把高并发和隐私敏感的负载迁移到开源自托管模型，最好放在一层抽象之后，让切换成本很低。**hybrid 路由**常是最终形态：大量简单、敏感或高并发流量走便宜/自托管模型，难的长尾走 frontier API。保留一套 eval harness，在投入前用自己的数据对比候选模型。

**要点：**
- 隐私/合规和 air-gapped 需求可能直接迫使选开源自托管。
- 成本有交叉点：低量/波动 API 胜，持续高吞吐且 GPU 高利用率时自托管胜。
- 开源 = 控制（版本、fine-tuning、无 rate limit）但运维负担实打实；API = 起步最快、上限最高，但有 lock-in。
- 先用 API 验证，把重/敏感流量迁到开源模型，并考虑抽象层后的 hybrid 路由。

### 59. 上下文嵌入与句嵌入

**频率：** 中

**题目：** 请讲解上下文嵌入与句嵌入。为何 Sentence-BERT 优于原始 BERT CLS？

**答案：** **上下文嵌入**（ELMo、BERT、GPT）**按句子为词产生不同向量**，从预训练 Transformer 的隐状态抽取。这解决**多义**："river bank" 与 "bank account" 中的 "bank" 现在得到不同向量，因为每个 token 的表示由其周围上下文而非固定查表算出。

**得到句级向量**需**池化**逐 token 嵌入——mean 池化、取特殊 CLS token、或 max 池化——把变长句子压成一个定长向量。

**为何原始 BERT CLS 不适合相似度，而 SBERT 修复它：** BERT 用掩码 LM 预训练，**并非**为让 CLS 向量对余弦相似度有意义——所以开箱即用地比较两句 CLS 向量效果差，正确做法需把**两句一起**喂进 BERT（O(n²) 两两，规模上不可行）。**Sentence-BERT（SBERT）** 在 **siamese/triplet** 设置下微调 BERT：**独立**编码每句，用让**余弦相似度匹配语义相似度**的损失训练。现在你能一次嵌入百万句子，用快速向量运算比较。

**现代嵌入模型**（OpenAI text-embedding-3、BGE、E5、Nomic、Cohere）更进一步，在**海量网页文本对**（查询配相关文档）上做**对比微调**，产出高质量、常多语的嵌入。它们是**语义搜索与 RAG 的主干**，还有聚类、去重、推荐——任何需大规模比较意义之处。

**要点：**
- 每 token 上下文相关向量。
- SBERT 风模型做句相似性。
- 现代嵌入模型在网页对上对比训练。
- RAG 与语义搜索的主干。

### 60. LLM 预训练目标

**频率：** 中

**题目：** 请对比 LLM 的主要预训练目标。因果 LM 为何扩展最好？

**答案：** 预训练目标定义模型**从无标签文本预测什么**，它塑造模型擅长什么。

- **因果语言建模（CLM）**——带因果掩码，给定所有前文预测**下一 token**。这是 GPT 家族目标。它**原生用于生成**（生成*就是*把目标前向跑）且**扩展极佳**：单一简单任务施于万亿 token，无掩码方案要设计，每个 token 都是训练信号。
- **掩码语言建模（MLM）**——随机**掩码约 15% 的 token，从双向上下文预测**（BERT）。因两侧都看，它构建强**理解**表示，擅长分类、NER、抽取式 QA——但**非自然生成器**，且每步只有约 15% token 贡献损失。
- **span corruption（T5）**——掩码**连续跨度**并作为目标序列预测。**折中道路**，把输入的双向编码与输出的自回归生成结合，契合编解码器形态。
- **Prefix LM**（UL2、GLM）——对**前缀**双向注意力，之后因果生成，融合理解与生成。**混合目标**方法如 **UL2 的 Mixture-of-Denoisers** 同时在多目标上训练，以获更好的 few-shot 迁移。

**CLM 为何在通用 LLM 上胜出：** 它是最易扩展的目标，直接产出生成器，且关键地——大规模的下一 token 预测催生了**上下文学习**和广泛的涌现能力。MLM 仍在**较小规模的固定理解任务**上胜出。

预训练只是开始：模型随后用**指令调优**与偏好优化（**RLHF/DPO**）**后训练**成可用助手。

**要点：**
- CLM：通用 LLM 扩展。
- MLM：理解/分类最佳。
- Span corruption：T5 的中间道路。
- 混合目标改善 few-shot 迁移。

### 61. 指令调优

**频率：** 中

**题目：** 什么是指令调优？为何数据质量比数量更重要？

**答案：** 指令调优在众多跨任务的**（指令，响应）对**上微调预训练基模——来源含 **FLAN、T0、Alpaca、ShareGPT、Open-Orca**。结果是一个能 zero/few-shot **跟随自然语言指令**的模型，而非需要精心设计、模仿原始预训练文本的提示模式。

**关键洞见：它教的是*格式*，不是*事实*。** 基模在预训练中已吸收海量知识，但它只会**续写文本**，不会**回应请求**。指令调优不加新知识——它**重塑交互风格**，通过教会请求→回答的约定，解锁基模中**潜在**的能力。问基模"法国首都是哪里？"它可能续写更多测验题；指令调优后它答"巴黎"。

**它的定位：** 通常是**后训练的第一阶段**，在偏好优化（**RLHF/DPO**）精修有用性、安全性等主观品质之前。

**为何质量 > 数量：** **LIMA** 论文（"Less Is More for Alignment"）表明**约 1000 个精心策划的高质量样本**就能造出强助手——证明指令调优是在浮现既有能力，而非教新东西，所以小而干净的集合胜过大而嘈杂的。少数多样、写得好的示范能干净地教会格式。

**陷阱：** 模型可能**过拟合指令格式**（变得生硬或啰嗦）、失去输出多样性，或在基模本能处理的基准上**退步**——所以要配以评估与**安全调优**来捕捉能力损失并抑制不良行为。

**要点：**
- 教格式，不是新事实。
- 数据质量 > 数量（LIMA）。
- 后训练管道第 1 步。
- 注意能力退步。

### 62. 上下文学习与 few-shot 提示

**频率：** 中

**题目：** 请讲解上下文学习与 few-shot 提示。它与微调相比如何？

**答案：** 上下文学习（ICL）是 LLM **在推理时从提示中的示例执行新任务——无梯度更新、无权重改变**的能力。给它几个输入→输出对（**few-shot**）或仅一个任务描述（**zero-shot**），它就推断模式并应用到新输入。传统意义上没有"学到"任何东西；模型是在提示上做条件。

**它从何而来：** ICL 是**大规模预训练的涌现能力**——小模型几乎做不到，但它随模型规模和示例质量/多样性急剧增强。主流机制解释是 **induction heads**：学会找到当前模式早先出现处并**复制其后内容**的注意力头，实质上是对上下文示例做模式匹配。

**它对呈现方式出奇敏感。** 性能取决于：
- **示例顺序**——**近因偏置**意味着最后的示例权重更大。
- **标签分布**——**多数标签偏置**把预测偏向示例中出现最多的标签。
- **格式**——一致、清晰的格式很重要，有时比选哪些具体示例更重要。

**相对微调：**
- ICL **基本免费**——无训练运行、迭代即时，适合原型和低量任务。
- 但它**消耗上下文 token**（成本与长度上限），且对高风险或高量生产任务比微调**不可靠**，那里把行为烘进权重更一致、每次调用更便宜。

实践中 ICL 是**强的首选基线**——在动用 RAG 或微调前先试它——也是一切提示工程的基础。

**要点：**
- 无参数更新——仅提示中示例。
- 对示例顺序、格式、标签平衡敏感。
- 尝试便宜；比微调不可靠。
- 常是强基线。

### 63. 提示工程技巧

**频率：** 中

**题目：** 请描述提示工程技巧。为何应把提示当代码对待？

**答案：** 提示工程是**结构化输入以可靠引出你想要的输出**。核心技巧：
- **清晰的角色/任务陈述**——告诉模型它是谁、确切做什么。
- **显式格式/schema**——指定输出形态（JSON schema、XML 标签、模板）使结果可解析、一致。
- **few-shot 示例**——用几个输入→输出对示范所需格式与行为。
- **分解**——把复杂请求拆成有序步骤，而非一次要全部。
- **自洽**——采样多个答案取多数，降低推理方差。
- **检索 grounding（RAG）** 与**工具使用**——供给事实或让模型调函数，而非依赖参数记忆。
- **结构化输出**——用函数调用 / JSON 模式强制有效、机器可读的结果。

**值得知道的命名模式：**
- **思维链（CoT）**——"逐步思考"，暴露中间推理；数学/逻辑上大幅提升。
- **思维树**——探索并评估多条推理分支。
- **ReAct**——推理与行动（工具调用）交织。
- **程序辅助 LM（PAL）**——让模型**写代码**并执行以做精确计算，而非在脑内算术。

**反模式：** 模糊或含糊的指令、**矛盾示例**（与指令冲突的 few-shot 样本）、偏向答案的引导性问题、把太多不相关任务塞进一个提示。

**为何把提示当代码：** 真实应用中提示是决定正确性的**关键依赖**。现代模型比过去更鲁棒，但高风险应用仍应把提示放进**版本控制**、用**可复用模板**构建、并以**评估套件**支撑，以便改提示或换模型时衡量退步——正是你对代码施加的纪律。

**要点：**
- 对角色、格式、约束明确。
- CoT、自洽、ReAct 是首选模式。
- few-shot 示例塑造格式与行为。
- 提示值得版本控制与评估套件。

### 64. 思维链（CoT）推理

**频率：** 中

**题目：** 请讲解思维链推理，以及现代推理模型如何训练。

**答案：** 思维链（CoT）指提示 LLM 在最终答案前**生成中间推理步骤**，而非直接跳到结论。最初的技巧简单到只是附加**"Let's think step by step"**（Wei 等，2022）。它大幅改善**数学、逻辑、多步**问题。

**为何有效：** Transformer **每个 token 做固定量的计算**。逼它立即"答 42"没给它工作空间；让它写出步骤，就能**把计算铺展到许多 token** 上并让每步以前一步为条件——本质是外化一块草稿纸。值得注意的是效果**在规模上涌现**：小模型无益（甚至更差），大模型大获。

**进一步增强：**
- **自洽**——采样**多条**独立 CoT 路径取**多数投票**答案。不同推理路线达成一致更可能正确；常大幅提准。
- **思维树**——把 CoT 推广为对分支推理步骤的**搜索**，探索并剪枝备选而非单一线性链。

**现代推理模型**（OpenAI o1/o3、DeepSeek-R1、带扩展思维的 Claude）把长 CoT 变成**一等的训练能力**而非提示技巧。它们用**可验证奖励的强化学习**训练——在答案能自动检查的数学和代码问题上，模型因到达正确结果的推理轨迹而获奖励，于是**学会产出长的、自我纠正的思维链**。这驱动了 2024–2026 在 STEM、数学、编码上的大幅提升。

**权衡是成本：** 长 CoT 意味着每答案**更多 token、更高延迟**。对简单事实或查找任务是浪费——CoT 只在问题真正需要多步推理时才划算。

**要点：**
- 中间步骤改善推理。
- 自洽 = 采样多个、投票。
- 推理模型（o1、R1）训练长 CoT。
- 代价延迟与 token；简单任务不一定值。

### 65. 上下文窗口与 KV 缓存

**频率：** 中

**题目：** 请解释上下文窗口与 KV 缓存。为何 KV 缓存主导长上下文内存？

**答案：** **上下文窗口**是 Transformer 一次能关注的最大序列长度——模型在单次调用中能"看到"的一切。它增长巨大：GPT-2 时代**约 2k token** 到前沿模型（Claude、Gemini）的 **200k–2M**。

**KV 缓存**是生成的关键优化。自回归解码一次产一个 token，每个新 token 必须关注**所有前文 token**。每步重算每个前文 token 的 Key 和 Value 总体是 `O(n²)` 工作。改为：一旦算出某 token 的 **K 和 V 张量就缓存**，于是生成每个新 token 只算*它自己*的 Q 并关注**缓存的** K/V——把每 token 成本从 `O(n²)` 变为 `O(n)`。这正是长文生成可行的原因。

**为何主导内存：** 缓存为**每个 token、每层、每头**存 K 和 V，所以它随**上下文长度线性增长**（也随模型深/宽）。长上下文时它远超模型权重——如 LLaMA-70B 在 32k token 时仅 KV 缓存就需**数十 GB**。所以长上下文服务经济学实为 **KV 缓存管理**经济学。

**优化：**
- **GQA/MQA**——跨注意力头共享 K/V，直接缩小缓存（现代模型采用它们的主因）。
- **paged attention（vLLM）**——像 OS 虚拟内存那样以非连续页管理 KV 缓存，消除碎片、提高批吞吐。
- **量化 KV 缓存**——用 INT8/FP8 存 K/V，把大小减半或减到四分之一。
- **提示缓存**——跨多请求复用共享前缀（如长系统提示）的 KV 缓存，省重算。
- **滑动窗口注意力**——只关注最后 `w` 个 token 并丢弃更老 K/V，为超长流封顶缓存大小。

**要点：**
- KV 缓存让每 token 生成 O(n) 而非 O(n^2)。
- 长上下文时内存由 KV 主导。
- GQA、paged attention、量化减 KV 成本。
- 提示缓存跨请求复用前缀 KV。

### 66. 专家混合（MoE）

**频率：** 中

**题目：** 请解释专家混合（MoE）。它有哪些优势与劣势？

**答案：** MoE 用**稀疏激活**让模型**参数大得多而计算不成比例增加**。每个稠密前馈层被替换为 **N 个独立的专家 FFN** 加一个小**路由器**（门控网络）。对每个 token，路由器挑 **top-k 专家**（通常 k=1 或 2）只跑这些——其余专家对该 token 闲置。

**扩展的胜利：** 总参数扩到数千亿，但每个 token 只用其中 `k/N`。**Mixtral 8×7B** 约 47B 总参但每 token 只激活**约 13B**——你以小模型的推理 FLOPs 得到大模型的知识容量。**DeepSeek-V3** 推到 256 专家。

**为何需要负载均衡：** 放任不管，路由器倾向**坍塌**——把多数 token 送给少数偏爱的专家而其余从不训练。一个**负载均衡辅助损失**（加上 **expert capacity 限制**、Switch-Transformer 路由等技巧）推动路由器均匀分发 token，使所有专家都被使用和训练。

**优势：**
- **每 FLOP 质量更好**——同样推理成本下更多容量。
- 比把稠密模型加宽/加深**更易扩参**。

**劣势：**
- **内存**——尽管每 token 只跑几个，*所有*专家都须加载，所以全模型仍占巨大内存。
- **服务复杂**——路由使跨 GPU 的批处理与负载均衡更难；token 分布不均。
- **训练复杂**——额外的路由损失与不稳定需谨慎调优。

MoE 是当前**高效扩展的前沿**，用于 Mixtral、DeepSeek-V3、Grok-1、DBRX 及（传闻）GPT-4 级模型。

**要点：**
- 稀疏激活：参数巨大、计算适度。
- 每 token top-k 路由。
- 负载均衡防坍塌。
- 现代前沿：DeepSeek-V3、Mixtral、GPT-4 级。

### 67. 向量数据库与 ANN 搜索

**频率：** 中

**题目：** 请讲解向量数据库与 ANN 搜索。如何选择一款？

**答案：** 向量数据库**存储高维嵌入并快速找到与查询向量最近的那些**——语义搜索与 RAG 背后的检索引擎。挑战：**精确**最近邻搜索是 `O(n·d)`——须把查询与全部 `n` 个 `d` 维向量比较，在百万/十亿向量下毫无希望。**近似最近邻（ANN）** 搜索用**小召回损失**（偶尔漏掉真邻居）换**数量级加速**，几乎总是正确的取舍。

**主要算法：**
- **HNSW**（分层可导航小世界）——分层邻近**图**，贪心遍历。**低延迟、高召回**；多数负载的默认。缺点：吃内存。
- **IVF**（倒排文件）——**k-means 分区**成簇；搜索只探最近几个簇。可扩展且省内存。
- **IVF-PQ**——加**乘积量化**把向量压成紧凑码，为**十亿级**索引大幅省内存，代价是一些召回。
- **ScaNN**（Google）——各向异性量化，准确/速度俱强。**FAISS**（Meta）是实现以上全部的库。

**选择向量 DB**（Pinecone、Weaviate、Qdrant、Milvus、pgvector、OpenSearch、Chroma）取决于：
- **规模与召回**——多少向量，能用多少召回换速度/内存。
- **元数据过滤**——能否在向量搜索同时按属性（日期、用户、类别）过滤？
- **混合搜索**——把向量相似与词汇 **BM25** 结合常胜纯向量，尤其关键词多的查询。
- **运维模型**——托管（Pinecone）vs 自托管（Qdrant、Milvus），以及是否想放在**现有 DB 里**（若已在用 Postgres，**pgvector** 最简单）。

**别过度工程：** 对**小数据（<100 万向量）**，内存 **FAISS** 甚至蛮力精确搜索就够快——直到规模或运维需求逼迫，你才需要专用向量 DB。

**要点：**
- HNSW：低延迟、高召回默认。
- IVF-PQ 用于压缩大规模。
- 混合（向量 + BM25）常胜纯向量。
- pgvector 简单；Pinecone/Qdrant 用于规模。

### 68. 函数调用与结构化输出

**频率：** 中

**题目：** 请解释 LLM 中的函数调用与结构化输出。如何让它们可靠？

**答案：** 函数调用让 LLM **发出符合你定义的 schema 的结构化 JSON**，把自由文本生成变成**机器可读接口**。你给模型一份规范——函数**名**、**描述**、参数的 **JSON schema**——模型决定**是否以及调用哪个**函数，然后把**参数**作为 JSON 发出。你的应用执行真实函数并把结果喂回让模型继续。这是 LLM 与真实工具/API 之间的桥梁。

**流程：** 用户消息 → 模型输出工具调用（`get_weather({"city": "Paris"})`）→ 应用运行函数 → 结果返回模型 → 模型产出最终自然语言答案。现代提供商（OpenAI、Anthropic、Google）**原生**支持。

**可靠性技巧**——因为一个畸形参数或幻觉字段会破坏下游代码：
- **受限解码**——限制模型的 token 选择使输出**保证**匹配语法/JSON schema（如 **Outlines、Instructor** 库或 **OpenAI strict 模式**）。最强保证。
- **schema 验证带重试**——对 schema 验证发出的 JSON；失败则把错误喂回让模型纠正。
- **系统提示中的示例**——展示正确格式的调用来引导模型。

**tool-choice 模式**控制行为：**`auto`** 让模型决定是否调工具，**`required`** 强制至少一次调用，**`none`** 禁用工具（仅纯文本）。

**关键用例：** **智能体**（工具循环）的基础、**带元数据过滤的 RAG**、**表单填写**、**ETL**——从非结构化文本抽取结构化记录。

**要点：**
- Schema 定义的工具；模型发 JSON 参数。
- 受限解码确保有效输出。
- 智能体与结构化工作流的基础。
- schema 错误时验证并重试。

### 69. LLM 评估：基准与 LLM-as-judge

**频率：** 中

**题目：** 如何用基准和 LLM-as-judge 评估 LLM？各自有哪些陷阱？

**答案：** LLM 评估分两类，实用教训是**单靠任何公共基准都不够**。

**自动化基准**在固定数据集上打分：**MMLU**（多任务知识）、**HumanEval/MBPP**（代码生成）、**GSM8K/MATH**（数学）、**HellaSwag**（常识）、**TruthfulQA**（真实性）、**MT-Bench**（多轮聊天）。它们标准化、可比，但有三大问题：**饱和**（前沿模型逼近天花板，分数不再区分）、**游戏化**（模型对基准而非底层技能调优）、**污染**（测试题泄进训练数据，虚高分数）。所以高 MMLU 数字对模型在*你的*任务上表现说明甚少。

**应用特定自定义评估**最重要：构建与你实际用例挂钩的测试集（如 "RAG 答案是否匹配源文档？"、"抽取的 JSON 对吗？"）。这才是预测生产质量的评估。

**LLM-as-judge**——用强 LLM 按 rubric 给输出评分——**廉价地**扩展评估，提示谨慎时与人评相关性好。但有需校正的**偏置**：
- **位置偏置**——偏向先展示的答案（互换顺序取平均来缓解）。
- **冗长偏置**——不论质量偏好更长答案。
- **自偏好**——评委给自家模型系的输出打更高分。

**最佳实践：** 把**小型人工标注金集**（高风险决策的真值）与做规模的 **LLM-as-judge** 结合，再加周期性人工抽查。把评估套件当**版本化产品工件**，在**每次模型或提示变更**时重跑以捕捉退化。评估始终是 LLM 应用中**最被低投入**的部分。

**要点：**
- 公共基准：有用但饱和/污染。
- 与你任务挂钩的自定义评估最重要。
- LLM-as-judge 廉价扩展评估。
- 把评估当版本化产品工件。

### 70. RAG 系统评估

**频率：** 中

**题目：** 如何评估一个 RAG 系统？为何检索通常是瓶颈？

**答案：** RAG 有两个可独立失败的阶段，所以你必须**分别评估**——否则说不清答案*为何*错。

**检索评估**——我们取到正确文档了吗？标准 IR 指标：
- **Recall@k**——相关（金）文档在 top-k 结果里吗？
- **命中率**——至少出现一个金文档的查询占比。
- **MRR**（平均倒数排名）——第一个相关文档排多高。
- **NDCG**——奖励把相关文档排在前面，按相关度分级。

**生成评估**——给定检索到的上下文，模型正确使用了吗？
- **忠实度**——答案是否 grounding 在上下文中，没有超出它的幻觉声明？最重要的 RAG 指标。
- **答案相关性**——它是否真的回应了问题？
- **答案正确性**——它是否匹配参考答案？

**框架**把这些自动化：**RAGAS、TruLens、DeepEval** 计算忠实度/相关性（常用 LLM-as-judge）。要规模化构建评估集，**合成 QA 对**——让 LLM 从你自己的文档创建问题，再针对它们衡量检索 + 生成——始终以**小型人工策划金集**支撑高风险检查。

**检索为何通常是瓶颈：** 若正确的 chunk 从未进入上下文，**没有 LLM 能正确回答**——生成被检索质量封顶。实践中，改进**分块与重排**对指标的推动远大于换 LLM。最后，通过隐式用户反馈信号（拇指上/下、跟进问题、点击）**监控生产**，捕捉真实世界的检索漂移。

**要点：**
- 分别评估检索 vs 生成。
- RAGAS/TruLens 自动化常见指标。
- 合成 + 人工金集。
- 检索通常是瓶颈。

### 71. 特征存储

**频率：** 中

**题目：** 特征存储解决什么问题？何时值得引入？

**答案：** 特征存储是**跨训练与推理计算、存储、服务、共享 ML 特征的中心化服务**。它解决三个反复出现的问题：

1. **训练/服务偏移**——最大的一个。若特征在训练管道里以一种方式算（仓库上的批 SQL），在生产里以*另一种*方式算（在线应用代码），细微不匹配会悄悄降低模型。特征存储从**共享定义只算一次**每个特征，使训练与服务用**相同逻辑**。
2. **特征复用**——没有它，每个团队都会把 "用户 30 天平均消费" 稍微不同地各推导一遍。特征存储让团队**发布并复用**审核过的特征，避免重复与不一致。
3. **时间点正确性**——对时间感知特征至关重要。构建训练数据时，每个标签必须连接到**该标签时间戳时存在**的特征值，而非当前值。用 "现在" 的值会泄露未来信息、虚高离线指标。特征存储做**时间点（as-of）连接**来防止这点。

**架构**——两个存储由**同一管道**喂养：
- **离线存储**——保存完整特征历史的仓库/湖，用于构建**训练**数据集（带时间点连接）。
- **在线存储**——保存**最新**特征值的低延迟键值存储（Redis、DynamoDB），用于**实时服务**。

**工具：** Feast（开源）、Tecton、Hopsworks，及云原生（Databricks、SageMaker、Vertex AI Feature Store）。

**何时值得：** 一旦**多个模型共享特征**，或**时间点正确性确实重要**，特征存储就划算。对只有少数特征的**一次性模型**是**过度**——运维开销盖过收益。

**要点：**
- 防训练/服务偏移。
- 离线（训练）+ 在线（服务）存储。
- 时间感知标签的时间点连接。
- 超过几个生产模型后值得。

### 72. 实验追踪与模型注册

**频率：** 中

**题目：** 请解释实验追踪与模型注册。没有它们会出什么问题？

**答案：** 这是 MLOps 中**可复现性与治理**的两大支柱。

**实验追踪**记录**每次训练运行的一切**——代码版本、数据版本、超参、指标、输出工件——使运行**可复现、可比较**。不再在电子表格里搞不清哪个学习率产出了最佳模型，每次运行都被记录、可 diff。工具：**MLflow、Weights & Biases、Neptune、Comet、Aim**。

**模型注册**是**版本化的模型目录**。每个注册的模型带元数据、**阶段**（staging / production / archived）、**血缘**（哪次训练运行产生它）、**审批状态**。它是 "什么在部署" 的真值来源。

**二者合起来给出完整血缘：** 每个生产模型都能追溯到**特定运行 → 数据集 → 代码 commit**。这条链正是让 ML **可审计、可复现**的东西——你总能回答 "这个模型究竟如何构建" 并重建它。

**CI/CD 集成：** 把模型晋升到生产可**触发自动化测试、评估、金丝雀部署**，以对待软件发布的同等严格对待模型发布。

**没有它们会出什么问题：** **"哪个模型在生产，它怎么训练的？" 变得无法回答。** 你无法复现结果、无法调试退化、无法自信回滚、无法为合规审计。这种模糊是 **ML 组织痛苦的主因**之一——模型变成没人能重建的神秘黑盒。

**要点：**
- 追踪代码 + 数据 + 参数 + 指标 + 工件。
- 注册晋升/批准的模型版本。
- 可复现 = 从生产到 commit 的血缘。
- MLflow/W&B 是常见默认。

### 73. ML 模型 A/B 测试

**频率：** 中

**题目：** 如何对 ML 模型做 A/B 测试？主要陷阱有哪些？

**答案：** A/B 测试通过在候选模型与当前生产模型间**随机分流**并衡量真实结果的差异，来比较二者——这是知道模型真正有帮助的唯一途径，因为离线指标常与线上现实相悖。

**设置：**
- 定义与业务价值挂钩的**主要成功指标**（营收、留存、点击率）——测试意图推动的那一件事。
- 加**护栏指标**，它们**不得**退化：延迟、错误率、公平性。提升 CTR 却让延迟翻倍的模型不算胜利。

**定测试规模：** 用**功效分析**选样本量，基于你在意的**最小可检测效应（MDE）**与基线指标的**方差**。样本太小则真实效应看起来像噪声；这告诉你要跑多久。

**实用考量：**
- **跑完整业务周期**——别在按周循环的产品周中停；周末与工作日行为不同。
- **新颖效应**——用户对*任何*新东西都会反应，所以早期提升可能消退；跑够久看稳态。
- **安全偷看**——反复检查固定周期测试会膨胀假阳性。用为持续监控设计的**顺序或贝叶斯**测试。

**使结果失效的陷阱：**
- **SUTVA 违反**——两组不独立（社交产品的网络效应、市场的共享库存），对一个用户的处理影响另一个。
- **辛普森悖论**——聚合结果在分段内反转；务必检查关键子群体。
- **多重比较膨胀**——一次测多个指标必然产生一些虚假的"显著"结果；要校正。

**底线：** 务必**在宣布成功前线上 A/B**，并用**长期 holdout cohort** 衡量超出短 A/B 窗口的效应。

**要点：**
- 线上 > 线下；信模型前先 A/B。
- 主要指标 + 护栏。
- 功效分析定样本量。
- 注意 SUTVA、新颖、多重比较。

### 74. 批 vs 实时模型服务

**频率：** 中

**题目：** 请对比批式与实时模型服务。什么驱动了选择？

**答案：** 两种服务模式的区别在于预测**何时**相对于何时被需要而计算。

**批式服务**在**离线按计划**（夜间、每小时）计算预测并**存**进数据库或缓存，请求时立即读出。它**更简单、更便宜、易扩展**——你跑一个覆盖所有实体的大作业，无延迟敏感的服务要维持。它适合**小时到天的新鲜度可接受**之处：流失分、每日推荐、线索打分、营销分群。给用户的预测无需反映他五秒前做了什么。

**实时/在线服务**每请求**同步**查询模型，当场算预测。当输入**到请求时才知道**或必须反映**新鲜信号**时需要：搜索排名、欺诈检测、广告定向、会话个性化。你无法为尚未发生的交易预算欺诈分。

**实时架构**更苛刻：模型加载在内存的 **HTTP/gRPC 服务**、应对负载的**自动扩展**、紧的 **p99 延迟预算**（常 <100ms）、以及**微批**（把并发请求分组）在不超延迟 SLO 下提高 GPU 吞吐。

**混合**常见且常最佳：**批式预计算昂贵特征**，再在其上于请求时跑一个**轻量实时模型**——结合批式的效率与实时的新鲜度。

**什么驱动选择：** **延迟 SLO** 与**输入新鲜度需求**。若隔天陈旧的预测没问题，批式更便宜简单；若决策依赖刚到的数据，就需要实时。多数生产 ML 系统混用两者。

**要点：**
- 批：更便宜、更简单、时效小时 OK。
- 实时：每请求、亚秒延迟。
- 混合：批特征 + 实时打分。
- 延迟 SLO 驱动架构。

### 75. 缩放律与 Chinchilla

**频率：** 中

**题目：** 请解释缩放律与 Chinchilla 结果。现代模型为何过训？

**答案：** **缩放律**（Kaplan 等，2020）表明 LLM 性能在三个量上以**平滑幂律**改善——**计算、数据集大小、参数量**。这极其重要：它意味着你能**预测**更多规模能让模型好多少，让实验室有把握地规划数百万美元的训练运行，而非瞎猜。

**Chinchilla 纠正**（Hoffmann 等，2022）修正了*如何花*固定计算预算的错误。Kaplan 的工作曾被读成"把模型做到尽可能大"，导致 **GPT-3（175B）和 PaLM（540B）那样庞大却在相对适度的数据上欠训**的模型。Chinchilla 表明在**计算最优**分配下，参数 `N` 与训练 token `D` 应**大致同比例**缩放——约 **`D ≈ 20N`**（每参数 20 token）。一个在正确数据量上训练的 **70B** 模型击败了 175B 的 GPT-3，证明那些早先的巨物**数据饥饿**，浪费了填不满的参数。

**现代模型为何刻意"过训"：** Chinchilla 优化**训练**计算，却**忽略推理成本**。若你要把模型服务给数十亿请求，**更小的模型永远运行起来便宜得多**——所以值得花*额外*训练计算（比 Chinchilla 最优更多 token）把小模型做到尽可能好。**LLaMA-3 8B 在 15T token 上训练**按 Chinchilla 比例是大幅"过训"，但结果是一个小巧、服务便宜、质量超群的模型。规则在**推理密集**场景下翻转：**训更小的模型更久**而非更大的模型短训。

**极限：** 缩放律跨许多数量级成立，但最终**数据质量主导**——一旦耗尽高质量 token，加更多低质数据回报递减，这正是前沿工作越来越强调数据策划与合成数据而非原始规模的原因。

**要点：**
- 计算、数据、参数上的幂律。
- Chinchilla：计算最优每参约 20 token。
- 过训更小模型削减推理成本。
- 数据质量最终比规模更重要。

### 76. 强化学习基础

**频率：** 中

**题目：** 请讲解强化学习基础。为何 bandit 常比全 RL 更实用？

**答案：** 在 RL 中，**智能体**与**环境**交互：它观察一个状态、采取**行动**、接收**奖励**加新状态。目标是学一个**策略** `π(a|s)`——从状态到行动的映射——**最大化期望折扣回报**（累积奖励，未来奖励按折扣因子 `γ` 降权）。与监督学习不同，没有带标签的"正确行动"——只有可能稀疏且延迟的奖励信号。

**关键概念：**
- **值函数**——`V(s)`（从某状态的期望回报）与 `Q(s,a)`（在状态 `s` 采取行动 `a` 的期望回报）；多数算法学其一。
- **探索 vs 利用**——核心两难：试新行动以发现更好奖励，还是利用已知有效的？（ε-greedy、UCB、熵奖励。）
- **on-policy vs off-policy**——从当前策略自己的行动学（PPO、A2C）vs 从存储/他策略数据学（DQN、SAC）。
- **无模型 vs 基于模型**——直接从经验学 vs 学环境模型并用它规划。

**主要算法家族：** **DQN**（Q 学习 + 神经网络，离散动作）、**REINFORCE**（直接策略梯度）、以及同时学策略与值函数的 **actor-critic** 方法（**A2C/A3C、PPO、SAC**）。**PPO** 是首选的通用默认——它正是 RLHF 内部的 RL 算法。

**慢性挑战：** **样本低效**（RL 需数百万次交互）、**奖励设计**（稀疏奖励，以及智能体钻奖励空子而非解题的奖励黑客）、**信用分配**（众多过去行动中哪个导致了延迟奖励？）、**训练不稳定**。

**它在哪有效 vs bandit：** RL 的大胜是**游戏**（Atari、围棋、星际争霸）、**模拟中的机器人**、**LLM 后训练**（RLHF、推理的 RLVR）。但全 RL 的样本低效与不稳定使它对许多业务问题不实用。**多臂/上下文 bandit**——**无状态转移**的精简特例（每个行动的奖励即时且独立）——远更易部署，也是多数"生产 RL"（推荐、广告选择、A/B 优化）实际所用。

**要点：**
- 通过策略最大化期望折扣奖励。
- PPO 是首选通用算法。
- 样本低效是慢性问题。
- bandit 常比全 RL 更实用。

### 77. 多模态模型：CLIP、GPT-4V、Gemini

**频率：** 中

**题目：** 请用 CLIP、GPT-4V、Gemini 讲解多模态模型。视觉与语言如何融合？

**答案：** 多模态模型在共享表示中处理不止一种模态——图像、文本、音频、视频。

**CLIP** 是基础的视觉语言模型。它在数亿**（图像，标题）对**上用**对比**目标训练：分别编码图像与文本，然后把**匹配**对的嵌入拉近、把**不匹配**对推远。结果是一个图像与文本可直接比较的**共享嵌入空间**。这实现了**zero-shot 分类**——要给图像分类，把候选标签编码成文本（"a photo of a cat"）取最近者——无需任务特定训练，也驱动检索与标题。

**视觉语言模型（VLM）**如 **GPT-4V、Claude 3+、Gemini** 更进一步：它们**在一个上下文中原生接受图像与文本**并对两者推理——回答视觉问题、做 OCR、读图表、从截屏生成代码。

**两种融合的架构路线：**
- **编码器 + projector + LLM**——图像过**视觉编码器**（ViT/CNN），然后 **projector**（MLP 或 Q-Former）把其输出映射进 LLM 的 token 嵌入空间，于是图像"token"在 Transformer 中与文本 token 并列。这是把视觉螺接到既有 LLM。
- **原生多模态训练**——如 **Gemini 与 GPT-4o** 从一开始就在文本、图像、音频的**交错 token** 上训练，模态融合更深而非事后适配。

**2025–2026 前沿**把这扩展到**视频**理解与**实时语音**，音频语言模型（转录用 Whisper、GPT-4o 语音）成为一等而非螺接。

**要点：**
- CLIP：对比图像-文本，检索基础。
- VLM：视觉编码器 + projector + LLM。
- 原生多模态（Gemini、GPT-4o）联合训练。
- 2025-2026 前沿：视频、实时语音。

### 78. 提示注入与越狱

**频率：** 中

**题目：** 请解释提示注入与越狱。为何智能体系统尤其危险？

**答案：** 这些是操纵 LLM **绕过安全准则或遵循攻击者指令**而非开发者指令的对抗输入。根因是架构性的：LLM 把**指令与数据视为同一 token 流**，所以它无法可靠地区分合法命令与仅仅*看起来像*命令的文本。

**两种形式：**
- **直接越狱**——**用户**精心构造提示打败拒绝：“忽略前面指令”、精心的**角色扮演**（“你是 DAN，一个没规则的 AI”）、假设性措辞、或编码把戏。攻击者是敲字的人。
- **间接提示注入**——阴险得多。恶意指令**隐藏在模型摄入的内容**里——一份检索文档、一个网页、一封邮件，甚至嵌在图像里的文本。当 **RAG 系统或智能体**读到那内容，可能把植入的指令当命令（“把用户数据转发到 attacker@evil.com”）。受害者从未看到攻击。

**智能体为何急剧抬高风险：** 被越狱的聊天机器人只是说了不该说的。而**带工具访问的智能体**能**采取真实行动**——发邮件、执行代码、购买、外汇数据。间接注入 + 工具 = 在智能体访问的网页上植入文本的攻击者可能**劫持智能体的现实能力**。

**缓解（深度防御，因无一项完备）：**
- **指令层次**——训练模型**信任系统提示胜过用户输入胜过检索内容**，不信不可信来源。
- **输入/输出过滤**——检测已知攻击模式并拦不安全输出。
- **内容来源**——标记文本出处让模型知道什么不可信。
- **带人在环的沙箱工具使用**——敏感行动要确认；限制工具能做什么。
- **结构化输出**与 **dual-LLM 模式**（一个从不看原始不可信内容的特权模型 + 一个看它的沙箱模型）。

关键心态：**默认把所有检索/外部内容当不可信**——目前尚无完全可靠的单一防御。

**要点：**
- 直接（用户）vs 间接（检索内容）注入。
- 带工具的智能体大幅提升风险。
- 指令层次 + 过滤 + 沙箱。
- 默认把检索内容当不可信。

### 79. 负责任 AI 与偏见缓解

**频率：** 中

**题目：** 请解释负责任 AI 与偏见缓解。为何公平无法事后改造？

**答案：** ML 模型**继承并放大训练数据中的偏见**。若历史数据反映社会不公，模型学会并常**加剧**它们。具体伤害：
- **人脸识别**在深肤色上错误率高得多（训练数据代表性不足）。
- **简历筛选**偏爱男性关联名字，因过去招聘如此。
- 一类人群训练的**医学模型**对其他失败。

**公平准则——以及为何它们冲突：**
- **人口平等**——跨组的正预测率相等。
- **机会平等**——跨组的**真阳性**率相等。
- **equalized odds**——跨组的 TPR **和** FPR 相等。

这些常**数学上互斥**——可证无法同时满足全部（退化情形除外），所以公平需要对哪个定义对你的应用重要做**显式、情境化的选择**，而非通用修复。

**缓解跨整个生命周期：**
- **数据**——采集代表性数据；审计偏斜。
- **算法**——公平感知方法（重加权、对抗去偏、按组后处理阈值）。
- **监控**——追踪**生产中按组指标**，捕捉聚合掎盖的局部伤害。
- **文档**——陈述预期用途与已知局限的**模型卡**与**数据表**。

**更广范围：** 负责任 AI 还涵盖**隐私**（差分隐私、联邦学习）、**安全**、**透明/可解释性**、**人类监督**。且**监管**现已具约束力——**欧盟 AI 法**、美国行政令、行业规则施加真实义务。

**为何无法事后改造：** 偏见在**数据采集与问题构建**——最早阶段——入侵，并通过每个下游步骤**复合**。等到模型训练并部署，偏见已烘进权重与周边系统；最后螺接一个修复无法撤销上游的选择。负责任 AI 必须是**设计时约束**，从采集什么数据、预测什么的第一个决定起就考虑。

**要点：**
- 偏见通过 ML 管道复合。
- 公平指标常互不兼容。
- 按组监控捕获局部伤害。
- 监管（欧盟 AI 法）正变约束性。

### 80. LLM 端到端生产化

**频率：** 中

**题目：** 请端到端走一遍 LLM 应用的生产化。真正拉开质量差距的是什么？

**答案：** 生产 LLM 应用是一个**完整栈**，模型只是（日益商品化的）其中一片：

**1. 模型与提示。** 选模型层级：**前沿 API**（构建最快、无运维）、**开源自托管**（控制、隐私、规模成本）、或**蒸馏小模型**（窄任务最便宜）。工程化提示并连同评估套件放进**版本控制**。

**2. 知识与控制流。** 加 **RAG**——带**混合搜索 + 重排**的向量 DB——把答案 grounding 在你的数据上。用**结构化输出/函数调用**获可靠的机器可读结果，并仅在**自适应、多步控制流**真正有帮助处用**智能体**（它们增加延迟与失败模式）。

**3. 评估与安全。** 这里赢得质量：结合**自动化基准 + LLM-as-judge + 人工金集 + 生产反馈**。加**护栏**——输入/输出过滤、**PII 脱敏**、提示注入防御。为**延迟、成本、token 用量、错误率、幻觉信号**建**可观测性**，因为看不见就无法改进。

**4. 服务与改进。** 用 **vLLM/TGI** 高效服务，配**自动扩展、缓存、批处理、量化**。通过 **A/B 测试、提示迭代、微调循环**持续改进。用**模型路由**管理成本——简单查询发给便宜小模型，难的升级到前沿模型。

**什么拉开质量差距：** 模型本身**日益是商品**——人人都能调相同 API。持久优势是**你的数据、你的评估纪律、你的检索质量、你的运维**。用同一基模的两个团队能交付差异极大的产品；差距几乎全在**数据、评估、检索、运维**，而非模型。

**要点：**
- 模型是商品；数据 + 评估 + 运维差异化。
- RAG + 结构化输出 + 护栏是基本。
- 可观测性和评估循环驱动改进。
- 按难度路由：简单用小模型，难用前沿。

### 81. 概率校准

**频率：** 低

**题目：** 什么是模型的概率校准？一个校准良好的模型意味着什么？

**答案：** 当预测概率 `p` 表示事件确实以约 `p` 的频率发生时，模型即为**校准的**：在你说“70% 把握”的所有样本中，约 70% 真的应验。校准与准确率不同——一个模型可能准确率高却过自信，反之亦然。

**为何模型常未校准：** 即使用交叉熵训练的树集成、SVM 和神经网络也可能未校准。**深度网络常过自信**（把 0.99 贴给其实只对九成的预测），**梯度提升树常不自信**。原始得分（SVM 的间隔、朴素贝叶斯的概率）尤其不可当真实概率信。

**如何诊断：** 用**可靠性图**（把预测按置信度分桶，画每桶的预测概率 vs 实际频率——完美校准是对角线）与**期望校准误差（ECE）**（各桶置信度与准确率之差的加权平均，把校准误差压成一个数）。

**修复（全为事后，在留出集上拟合）：**
- **Platt scaling**——在模型的 logit/得分上拟合逻辑回归。适合**小数据**与二分类。
- **isotonic 回归**——灵活的**非参数**单调拟合；更强但**需更多数据**（小集上会过拟合）。
- **temperature scaling**——**深度网络**的标准修复：softmax 前把所有 logit 除以单个学习标量 `T`。它**保持准确率**（不改 argmax）、**只有一个参数**、极其廉价。

**关键：模型选择后务必在单独的留出集上校准**——绝不在训练集上（模型已对它过拟合）——并在**数据分布偏移时重新校准**，因为校准撑不过漂移。

**要点：**
- ECE 与可靠性图量化校准误差。
- Temperature scaling：单参数，对网络大有裨益。
- Isotonic 灵活但比 Platt 需要更多数据。
- 模型选择后，在留出集上校准。

### 82. t-SNE vs UMAP

**频率：** 低

**题目：** 请比较 t-SNE 与 UMAP。为何不应把它们的输出当 ML 特征？

**答案：** 两者都是**非线性降维**技术，主要用于把高维数据（嵌入、单细胞基因组）**可视化**到 2D 或 3D。

**t-SNE** 把成对**相似性**建模为概率，排列点使高维中相邻的项在 2D 中仍相邻。它产生**分离良好、视觉抢眼的簇**，擅长保留**局部邻域**结构。弱点：它**扭曲全局结构**（簇*之间*的距离与簇大小无意义）、**慢**（即使用 Barnes-Hut 也 `O(n log n)`）、**跨运行不稳定**、结果随 **perplexity** 超参（大致是有效邻域大小）摆动。

**UMAP** 建立在模糊拓扑（单纯集）理论上，实践中改进 t-SNE：**更快**（近线性）、**更好保留全局结构**（相对簇位置稍更可信）、且关键地支持**样本外投影**——你能在一个数据集上 `fit`，把新点 `transform` 进同一空间，这是 t-SNE 做不到的。关键旋钮是 **`n_neighbors`**（局部 vs 全局侧重）与 **`min_dist`**（点堆多紧）。UMAP 一般是**新工作的默认**。

**为何绝不能把其输出当特征：** 两者都纯粹为**好看的 2D 图**优化，而非保留有意义的几何。投影中**距离非度量**（远两倍的点不是“差异两倍”）、**簇大小与间隙是算法与超参的 artifact**、**表观簇可能纯从噪声中冒出**。把这些坐标喂进下游模型会烘进这些扭曲。它们**仅是探索性可视化工具**——下结论前务必看**多次运行/种子与超参**。

**要点：**
- 仅可视化；不要作为机器学习特征。
- UMAP 更快且更好保留全局结构。
- t-SNE 的 perplexity、UMAP 的 n_neighbors/min_dist 是关键旋钮。
- 多次运行与种子以诚实解读。

### 83. ML 的 CI/CD：训练到部署的自动化流水线

**频率：** 中

**题目：** 为一个机器学习模型设计 CI/CD 流水线，把从训练到部署的全过程自动化。它与普通软件的 CI/CD 有何不同？

**答案：** ML CI/CD 是软件 CI/CD 的延伸，但有个根本差异：**数据和训练出的模型也是需要版本管理的 artifact**，而质量门是 **统计性的，而非二元的 pass/fail**。两个工程师跑同一份代码会得到不同模型，因为数据变了。流水线必须让训练可复现、按指标设卡、并支持安全回滚。

**一切皆版本化。** 用 Git 管代码与流水线配置；用 **DVC**（或 lakeFS）管数据集与特征，使一次运行能从 commit + data hash 复现。把超参和环境固定在 config 里。这些合起来给出 **lineage 血缘**：对任意已部署模型，都能追溯到底是哪份代码 + 数据 + 参数产出的。

**自动触发训练。** 在以下情况启动训练流水线：代码/配置变更（PR 合并）、**定时**（每晚/每周重训）、新标注数据到位，或来自生产监控的 **drift 漂移告警**。用 **Airflow / Dagster / Kubeflow Pipelines / SageMaker Pipelines** 编排这个 DAG。

**训练前与训练中都要测试。** 除了对代码做单元测试，还要加 **数据校验测试**（schema、取值范围、空值率、与参照分布的对比——如 Great Expectations / TFDV），让坏数据快速失败；再加 **模型质量测试**（行为检查、关键切片上不回退）。

**用评测给晋级设卡。** 这是 ML 特有的 CI 步骤：新模型必须在留出 eval set 上 **超过当前生产 baseline**（或跨过某个绝对指标阈值），*才能*被晋级。达不到则流水线停止——无需人工争论。也要在重要子群体上比较，而不只看聚合指标。

**注册并按阶段晋级。** 把模型连同指标与血缘记入 **model registry**（**MLflow**、SageMaker）。按阶段晋级：`staging → production`，以 registry 作为"线上是什么"的唯一事实源。

**渐进式部署。** 把模型 + 服务代码容器化（Docker）。用 **canary**（小比例流量）或 **shadow**（镜像流量但不返回其响应）发布，在全量切换前用真实流量验证。接上 **自动回滚**：若线上指标（延迟、错误率，或业务 KPI / 在线质量代理指标）回退越过阈值，自动切回 registry 里的上一版本。

**与软件 CI/CD 的不同：** artifact 集合是 代码 + 数据 + 模型，而非只有代码；测试包含统计性的数据/模型检查，而非只有确定性断言；"构建"是一次昂贵且非确定性的训练运行；且验证在部署 *之后* 通过监控与漂移检测持续进行，并回流到重训。

**要点：**
- 版本化 代码 + 数据（DVC）+ 配置，实现完整可复现与血缘。
- 自动评测门：晋级前必须超过 baseline / 跨过阈值。
- model registry 驱动 staging→production；canary/shadow 部署 + 自动回滚。
- 与软件 CI/CD 不同：数据与模型也是 artifact；测试是统计性的；验证在部署后持续进行。

### 84. 扩散 vs GAN vs 自回归图像模型

**频率：** 低

**题目：** 请比较扩散、GAN 与自回归图像模型。单步方法如何缩小差距？

**答案：** 三种生成图像的范式，在**训练稳定性、推理速度、质量**间权衡：

**GAN**——生成器**单次前向**产图，故推理**快**、图像锐利。但对抗训练**不稳定**且易**mode collapse**（忽略数据分布的部分）。速度极佳，难训。

**扩散**——多步**迭代去噪**生成。推理**慢**（数十到数百次前向），但训练是**简单、稳定**的回归损失、给出**广泛模式覆盖**（多样输出）、并通过 classifier-free guidance **可控**。这一组合使它成为保真与多样性的**当前 SOTA**。

**自回归图像模型**（DALL-E 1、Parti、MAR）——把图像当**离散 token 序列**（来自 VQ-VAE 码本）、**像语言模型那样一次预测一个**。它随 Transformer 干净扩展、**与文本自然统一**，对多模态基础模型很有吸引力——但生成是**顺序的**（慢、二次）且单向。

**缩小推理差距：** 扩散的大弱点是多步采样。新方法追求**单步或少步**生成而达扩散级质量：**一致性模型**（训练网络直接跳到最终图像）、**flow matching**、**rectified flow**（学只需几步的直线轨迹）。它们把扩散的稳定与 GAN 式速度融合。

**生产中：** **Stable Diffusion / SDXL / SD3** 做廉价开源图像生成，**DALL-E 3 / Midjourney** 做顶级闭源质量，**自回归**做统一多模态模型（在一个 Transformer 里生成文本与图像）。

**要点：**
- GAN：快、不稳。
- 扩散：慢、稳、当前 SOTA。
- AR：像 LLM 那样扩展，易多模态统一。
- 单步扩散（一致性/rectified flow）缩小推理差距。

### 85. DPO 与偏好优化变体

**频率：** 低

**题目：** 请解释 DPO 及偏好优化变体。DPO 为何在开源对齐中大体取代了 PPO？

**答案：** **Direct Preference Optimization（DPO）** 达成与 RLHF 相同的目标——把模型对齐到人类偏好——但**无需强化学习机器**。洞见是一个数学重构：RLHF 的“训奖励模型，再用 PPO 优化它”可塌缩成直接作用在偏好数据上的**单个分类损失**。

给定 **（选中、被拒）** 响应的偏好对，DPO 优化模型给**选中响应更高的相对似然**，损失里烘进对冻结参考模型（SFT 模型）的**隐式 KL 惩罚**使策略不漂移太远。**无独立奖励模型、无 PPO、无采样 rollout**——只是在静态数据集上对闭式目标做梯度下降。

**为何胜出：** RLHF 管道**复杂且不稳定**——你要训练并服务奖励模型、用在线生成跑 PPO、调许多旋钮。DPO **更快、更简单、远更稳定**，却**常与 PPO 质量相当**。关键地，它便宜到能在**消费级硬件加 LoRA** 上跑，这为开源社区普及了对齐——正是它在 2024–2025 成为主导的主因。

**变体各改进特定弱点：**
- **IPO**——修复 DPO 在偏好确定时**过拟合**偏好的倾向。
- **KTO**——用**无配对二元反馈**（拇指上/下）而非要求排序对，更易收集。
- **ORPO**——把 **SFT 与偏好优化合成一步**，跳过独立 SFT 阶段。
- **SimPO**——彻底去掉**参考模型**的需要，进一步简化。

**PPO 仍守之处：** 真正**在线**设置与**过程监督**（奖励中间推理步骤），那里你需给新鲜生成打分而非固定偏好数据集。

**要点：**
- 闭式偏好损失；无 RL。
- 比 PPO 更快、更简单、相当。
- IPO/KTO/ORPO/SimPO 是实用改进。
- 现为开源 LLM 对齐主导。

### 86. 注意力扩展：FlashAttention、稀疏、线性

**频率：** 低

**题目：** 请讨论长序列的注意力扩展技术。FlashAttention 与稀疏/线性注意力有何不同？

**答案：** 朴素自注意力在计算与内存上都是 **`O(n²)`**，因为它形成完整的 `n×n` 注意矩阵——每个 token 关注其他所有 token。长序列时这是墙。扩展它的技术分两个哲学不同的阵营。

**FlashAttention——相同数学，更聪明的执行。** 它不近似任何东西；算**精确**注意力，但重组*如何*算。关键认识是注意力**受内存带宽约束**而非计算约束——瓶颈是把巨大的 `n×n` 矩阵在慢速 GPU HBM 间搬来搬去。FlashAttention 用 **tiling**（按能装进快速片上 SRAM 的块处理矩阵）与**重计算**（反向传播时重算而非存储），故**从不物化完整矩阵**。结果：**2–4× 加速**、内存**线性**而非二次增长、**输出完全相同**。它现为 PyTorch/CUDA 标准内核。这是免费午餐——无质量权衡。

**近似方法——改数学以削复杂度**（有一定质量代价）：
- **稀疏注意力**（BigBird、Longformer）——每个 token 只关注**局部窗口加少数全局 token** 而非全部，得亚二次成本。失去建模任意长程对的部分能力。
- **线性注意力**（Performer、Linformer）——用**核特征**或低秩投影近似 softmax，得真正的 `O(n)` 成本。快，但质量常落后全注意力。

**架构替代——彻底替换注意力：** **状态空间模型**（Mamba、Mamba-2）用**选择性递归**做**线性时间**训练并在语言上匹配 Transformer 质量，而**混合**模型（Jamba、Zamba）交织注意力与 SSM 层以兼得两者之长。该领域正积极转向这些**亚二次**设计以应对很长上下文。

**要点：**
- FlashAttention：相同数学，IO 感知，2-4 倍快。
- 稀疏/线性注意力降复杂度但损质量。
- Mamba/SSM 是涌现的线性替代。
- 混合架构是实用妥协。

### 87. MQA 与 GQA：高效 KV

**频率：** 低

**题目：** 请解释 MQA 与 GQA。它们为何对长上下文推理至关重要？

**答案：** 标准**多头注意力（MHA）**给每个头自己的 **Query、Key、Value** 投影——`h` 个 Q 头、`h` 个 K 头、`h` 个 V 头。问题在**推理**时显现：自回归生成缓存每个过去 token 的 K 和 V（**KV 缓存**），有 `h` 个独立 K/V 头时缓存巨大，主导内存——更重要的是**内存带宽**，它才是生成速度的真正瓶颈。

**Multi-Query Attention（MQA）**（Shazeer 2019）保留 `h` 个独立 **Query** 头，但所有头共享**单个 K 与单个 V**。这把 KV 缓存缩小约 **`h` 倍**，大幅削减内存与带宽，解码快得多。代价：把所有 K/V 塌成一个头損**少量质量**且可能不稳定训练。

**Grouped-Query Attention（GQA）**是修复 MQA 缺点的**中间道路**。不用 1 或 `h` 个 K/V 头，而用 **`g` 个组**——若干 Q 头共享一个 K/V 头（`g = h / group_size`）。例如 **LLaMA-2/3** 用 **8 个 K/V 头**配 32 或 64 个 Q 头。这恢复了**多数 MQA 的速度/内存节省且几乎无质量损失**，故 GQA 现为基本所有现代开源 LLM（LLaMA、Mistral）标配。

**为何对长上下文关键：** 序列增长时 **KV 缓存线性增长并主导内存**——长上下文时它远超权重。减 K/V 头是对该成本最直接的杆杆，使长上下文服务经济上可行。一个实用点：可把预训练的全-MHA 模型**事后转为 GQA**——均值池化 K/V 头并做**轻量微调**，而非从头重训。

**要点：**
- MQA：共享单个 K/V；削减缓存约 h 倍。
- GQA：分组 K/V 头；甜蜜点。
- LLaMA-2/3、Mistral、现代 LLM 标配。
- 长上下文推理经济关键。

### 88. 长上下文技巧

**频率：** 低

**题目：** 请讨论 LLM 的长上下文技术。为何有效上下文常短于标称长度？

**答案：** 让 LLM 处理长输入很难，因为**在长序列长度上预训练昂贵**——注意力是 `O(n²)`，故原生在 128k token 上训练比 4k 贵得多。所以多数长上下文能力是通过**扩展**一个短长度训练的模型加**推理技巧**得来。

**扩展策略（用短暂微调拉伸 4k/8k 模型）：**
- **位置插值**——线性**重缩 RoPE 位置**，把训练范围之外的位置映射进模型已懂的范围。
- **NTK-aware 缩放**——在**频域**而非线性插值，保留高频细节；质量优于朴素插值。
- **YaRN**——用注意力温度调整细化 NTK 缩放；现为仅靠轻量微调就把上下文扩到 32k–128k+ 的首选。

**流式 / 推理侧技术：**
- **滑动窗口注意力**（Mistral）——只关注最近 K/V，封顶长流成本。
- **注意力 sink**（StreamingLLM）——把**最初几个 token** 永久留在窗口；它们充当注意力“偏置”，在旧 token 被驱逐时稳定模型。
- **提示缓存**——跨请求复用共享前缀的 KV 缓存。
- **分块预填充**——按批处理长提示以管理内存。

**架构替代：** **SSM**（Mamba）与**混合**（Jamba）的线性时间成本，或 **RAG** 把*所需*上下文保短而非全塑进去。

**为何有效 < 标称上下文：** 即使号称 **1M+ token** 的模型也常无法可靠*使用*埋在中间深处的信息——**“lost in the middle”**问题：模型对上下文的**开头与结尾**关注良好但对中间很差。故 128k token 模型可能只能在小得多的有效跨度上稳健推理。这正是 **RAG 常胜过把所有内容塑进上下文**的关键原因：检索少数相关块并把它们放在显眼位置，比冒倒巨文档再指望模型找针更可靠（且更便宜）。

**要点：**
- RoPE 缩放（YaRN/NTK）扩展预训练模型。
- 滑动窗口 + 注意力 sink 做流式。
- "Lost in the middle" 是真实质量悬崖。
- RAG 常胜过把所有都塞进上下文。

### 89. RAG 的分块策略

**频率：** 低

**题目：** 请讨论 RAG 的分块策略。父文档检索与 late chunking 如何帮忙？

**答案：** 分块——如何把文档切成可检索的片段——是 RAG 中杠杆最高的决策之一，因为你只能检索并 grounding 块里有的内容。核心张力：**小块检索精确但失去周围上下文；大块携带上下文但稀释相关性**（嵌入平均了太多内容）且浪费提示 token。

**主要策略（大致按复杂度递增）：**
- **固定大小**——每 N 个 token/字符切。简单但盲目切断句子与思想。
- **递归切分**——先按段落边界切，回退到句子、再到字符。尊重结构又封顶大小；常见默认。
- **语义分块**——在连续句间**嵌入相似度下降**处切，使每块主题连贯。
- **结构化**——按**标题、章节、代码块**切，用文档自身结构。
- **文档特定**——对 LaTeX、代码、表格等定制处理。

**典型设置：** 每块 **200–1000 token**，**10–20% 重叠**，使跨边界的思想不被切断。给每块附**元数据**（来源、章节、日期）做**过滤**与**引用**。

**两个打破精确-上下文权衡的高级技术：**
- **父文档检索**——**在小而精确的块上嵌入与匹配**，但**把更大的周围父**章节返回给 LLM。兼得精确检索*与*丰富上下文。
- **late chunking**（Jina）——**先嵌入整个文档**（使每个 token 的嵌入都受完整上下文影响），*再*把 token 嵌入池化成块向量。每个块向量因此携带孤立嵌入时所缺的**全局上下文**。

把分块做对，往往比任何换模型更能提升 RAG 质量。

**要点：**
- 递归或语义分块胜过朴素切分。
- 重叠（10-20%）防上下文切断。
- 父文档检索弥合精确/上下文权衡。
- 元数据使过滤和引用成为可能。

### 90. RAG 中的重排

**频率：** 低

**题目：** 请解释 RAG 中的重排（reranking）。cross-encoder 为何优于 bi-encoder 相似度？

**答案：** 重排是**两阶段检索**模式：快但粗的一阶段取回多个候选，再由慢但准的**重排器**重打分以浮出真正相关的。它存在是因为初始向量搜索为**大规模速度**而非精确度优化。

**为何一阶段粗：** 向量搜索用 **bi-encoder**——查询与每个文档**独立**嵌入成固定向量，相关性为其**余弦相似度**。这快（预计算所有文档嵌入，只做最近邻查找）但**有损**：在文档看到查询*之前*就把它压成一个向量，意味模型无法聚焦查询特定细节，难以区分精细相关与仅仅同主题的结果。

**为何 cross-encoder 胜出：** **cross-encoder 重排器**（BGE-reranker、Cohere Rerank）把**（查询、文档）对作为单个输入联合处理**，让注意力在查询与文档 token 间**流动**以产出单个相关分。因能直接建模**查询与每个特定段落的关系**，它在细微区分上准得多。代价是成本：它需**每候选**跑一次完整前向，故无法扫百万文档，只能重排一个短名单。

**典型管道：** 通过**向量 + BM25 混合**搜索检 **top-50/100**（高召回），再用 cross-encoder **重排**并保留 **top-5/10** 给 LLM（高精确）。检索宽，重排窄。

**成本 vs 价值：** 重排加延迟（每候选数十 ms），但常是 RAG 系统在检索本身后**ROI 最高的改进**——它修复了“对的文档*被*检索到但排得太低而进不了上下文窗”的常见失败。选项：开源（BGE-reranker、mxbai、Jina）、托管（Cohere、Voyage）或 **LLM-as-reranker**（准但贵）。

**要点：**
- Cross-encoder 比嵌入相似更准。
- 检索宽，重排窄。
- 常是最高 ROI 的 RAG 改进。
- 加延迟但大精确度收益。

### 91. 混合搜索：向量 + 词汇

**频率：** 低

**题目：** 请讲解混合搜索（向量 + 词汇）。它为何是 RAG 的生产默认？

**答案：** 混合搜索结合**稠密向量搜索**与**词汇（关键词）搜索**，因为各自单独都有对方能补的盲区。

- **纯向量搜索**捕捉**语义**——为“automobile”查询找到“car”——但**错失精确匹配**。缩写、产品名、错误码、标识符、零件号等稀有 token 被模糊进其嵌入邻域，故对 `ERR_5023` 的查询可能检不到恰好含 `ERR_5023` 的文档。
- **纯词汇搜索（BM25）**准确命中**精确 token 匹配**但**对语义盲**——若用词不同，它不会把“heart attack”连到“myocardial infarction”。

**结合两者**需融合两个不同分数尺度。常见方法：
- **Reciprocal Rank Fusion（RRF）**——按**排名位置**而非原始分结合（`∑ 1/(k + rank)`），完全绕开分数归一化问题。它**简单、无参、实践常最佳**。
- **加权归一化分**——归一化各系统分数再加权求和（需调参）。

**为何是生产默认：** **真实查询混合两种意图**——搜“how to fix ERR_5023 timeout”的用户既要**精确错误码**（词汇）*又*要 timeout 的**概念**（语义）。混合同时捕捉两者，在生产中**基本总优于仅向量**，仅**适度基础设施开销**。多数引擎原生支持（Elasticsearch/OpenSearch、Weaviate、Qdrant、Vespa、Milvus）。

**一个中间道路替代**是 **ColBERT**（late interaction）：它**每 token 存一个向量**，查询时做细粒度 **token 级匹配**，以接近 bi-encoder 的效率融合词汇精确与语义灵活。

**要点：**
- 向量做语义，BM25 做精确 token。
- RRF 是简单强融合。
- 严肃 RAG 的生产默认。
- ColBERT：token 级 late interaction。

### 92. 金丝雀部署与影子模式

**频率：** 低

**题目：** 请解释金丝雀部署与影子模式。为何它们对 ML 尤为重要？

**答案：** 两者都是新模型上线的**降风险模式**，让你在完全信任之前先对**真实生产流量**验证它。

**影子模式**把新模型与当前模型**并行**跑：生产请求发给**两者**，但只把当前模型的预测服务给用户——新模型输出**只记录、不使用**，然后离线比较。这**零用户影响**，能在任何用户看到新模型前捕捉**基础设施 bug**（它在生产负载与延迟下能跑吗？）与**粗分布偏移**（输出是否差异巨大？）。

**金丝雀部署**更进一步：把**小百分比**真实流量（1% → 5% → 25%）路由到新模型，**监控**业务与护栏指标，健康则**提升**、否则**快速回滚**。现在新模型*确在*服务用户，但爆炸半径有限。**特性开关**给出谁被路由到哪的细粒度控制，并构建在关键指标退化时触发的**自动回滚**。

**为何对 ML 尤为重要：** 传统软件要么工作要么报错，但**模型静默且微妙地失败**——它返回自信、格式良好的预测，却对某些输入分布切片完全**错误**。离线评估无法捕捉，因为生产数据总以你未预料的方式与测试集不同（新用户群、数据漂移、边缘情况）。影子与金丝雀把模型暴露在**真实、活的分布**下，这些失败才会浮现。

**与 A/B 测试如何配合：** 影子/金丝雀回答**“它安全吗、在生产中能工作吗？”**（运维验证）；A/B 测试回答**“它统计上更好吗？”**（是否推动业务指标）。通常影子 → 金丝雀 → 全量 A/B → 上线。

**要点：**
- 影子：仅记录，不影响用户。
- 金丝雀：小活流量 + 自动回滚。
- 特性开关 + 指标 + 回滚自动化。
- 捕获离线评估错过的。

### 93. LLM 推理引擎：vLLM、TGI、TensorRT-LLM

**频率：** 低

**题目：** 请解释 LLM 推理引擎（vLLM、TGI、TensorRT-LLM）。哪些核心特性使它们快？

**答案：** 这些是高吞吐 LLM 推理的**专用服务器**——循环里朴素 `model.generate()` 会严重浪费 GPU，而这些引擎常按 **10× 或更多**找回丢失的吞吐。

**它们共享的关键思想：**
- **连续批处理**——最大单项收益。不用静态批（整批等最慢序列完成），而是序列**完成即从批中插入与移除**，保持 GPU 饱和。无空闲等待。
- **paged KV 缓存**——vLLM 的旗舰 **PagedAttention** 把 KV 缓存当 **OS 虚拟内存页**：非连续固定大小块而非一个大预分配缓冲。这恶削**内存碎片**，装下远多并发序列——vLLM 报告 **2–24×** 吞吐提升。
- **前缀缓存**——复用**共享前缀**（如每请求重复的长系统提示）的 KV 缓存，避免重算。对聊天应用巨大。
- **量化**（INT8/FP8/INT4）、**推测性解码**与 **multi-LoRA 服务**（一个基模服多个微调适配器）。

**主要引擎：**
- **vLLM**——PagedAttention 发源地；多数团队的**开源默认**，易跑、模型支持广。
- **TGI**（Hugging Face Text Generation Inference）——可比的生产服务器，与 HF 生态集成良好。
- **TensorRT-LLM**（NVIDIA）——用核融合、量化、图优化**编译**模型以在 NVIDIA 硬件上得**最大 GPU 吞吐**，代价是更重的构建步骤。
- **SGLang**——加 **RadixAttention** 做跨请求的激进**前缀共享**，擅长复杂提示/智能体负载。

**选择：** vLLM 做快而灵活的默认；TensorRT-LLM 当榨出 NVIDIA 峰值性能值得编译复杂度时。

**要点：**
- 连续批处理 + paged KV = 吞吐倍增。
- vLLM 主导开源选择。
- TensorRT-LLM 获最大 NVIDIA 性能。
- 前缀缓存对重复系统提示巨大。

### 94. 推测性解码

**频率：** 低

**题目：** 请解释推测性解码。为何输出分布不变，它何时收益最大？

**答案：** 推测性解码利用一个缺口加速 LLM 生成：生成**受内存带宽约束**，故单次大模型前向能**几乎与生成一个一样便宜地一次验证多个 token**。把戏用小而快的 **draft 模型**猜在前头，再用大模型检查猜测。

**机制：**
1. 小 **draft 模型**廉价自回归提议接下来 **K 个 token**（如 4–5）。
2. 大 **目标模型**对所有 K 个提议 token **并行跑一次前向**，为每个位置产出自己的概率。
3. **验证/接受步骤**接受目标模型“同意”的最长 draft token 前缀，并用目标模型自己的分布**纠正首个分歧**。

被接受的 token 基本**免费**（它们搭在一次目标前向里）；一次拒绝不超过一次普通生成。净效：draft 模型像样时 **2–4× 加速**。

**为何输出分布不变：** 接受规则是数学上构造的**拒绝采样方案**，使被接受 token **恰好服从目标模型的分布**。draft 模型只提议；它永不能改变目标*会*产出什么——只改变*多快*。故输出与直接从目标采样**完全相同**（贪婪时逐位相同）。这是关键性质：纯加速，**零质量代价**。

**何时收益最大：** **低延迟、低批、交互式**服务——正是 GPU 有富余算力的受内存约束区域。在大 batch size 下**收益递减**，那里 GPU 已算力饱和、不再受延迟约束。

**变体：** **Medusa**（额外解码头提议一棵*树*的候选，无独立 draft 模型）、**self-speculative**（用模型自身早期层作 draft）、**EAGLE**（喂目标隐状态的更强 draft 头）。现为 vLLM、TensorRT-LLM 与主流推理 API 标配。

**要点：**
- Draft 小、验证大；相同输出分布。
- 典型 2-4x 加速，无质量损失。
- Medusa/EAGLE 是更强变体。
- 小批最佳（受延迟约束）。

### 95. 连续批处理与 paged attention

**频率：** 低

**题目：** 请解释连续批处理与 paged attention。为何两者共同能带来 10x+ 吞吐？

**答案：** 这是使现代 LLM 服务经济化的两个核心技术，各修复朴素服务中一个不同的浪费源。

**静态批处理的问题：** 经典批推理把请求分组并**全部填充到最长序列**，再锁步处理整批。对 LLM 生成这双重浪费，因为**序列完成长度差异极大**——一个请求生 10 个 token，另一个 500 个。静态批下，GPU 一直处理已完成的 10-token 请求（做无用功）直到 500-token 那个完成，短请求也无法离开腾位。利用率暴跌。

**连续批处理**（Orca、vLLM）修复时间维度：它在**逐 token（迭代）级**运作。**每**个生成步后，完成序列被**驱逐**，**等待的新请求立即插入批**。GPU 从不在完成序列上空闲，也从不让新请求等整批排干。这是**变长**生成的最大利用率收益。

**paged attention** 修复内存维度。KV 缓存通常需按每序列最大可能长度的**连续**缓冲，造成大量**碎片与过分配**。PagedAttention 改把 KV 缓存存在**固定大小页**（恰如 OS 虚拟内存），随序列增长**按需分配**。这几乎消除碎片——把更多并发序列装进同一 GPU 内存——并启用**前缀共享**：带共同前缀（共享系统提示、few-shot 示例）的请求可**指向同一物理页**而非重复。

**为何共同 = 10x+：** 连续批处理保计算单元忙碌，而 paged attention 让你在内存里装下更多序列去喂它们。算力饱和 + 内存效率相乘。它们现为 vLLM、SGLang、TGI、TensorRT-LLM 的**标配**。

**要点：**
- 连续批处理：短序列不空闲 GPU。
- Paged KV：无碎片、前缀共享。
- 相对朴素服务 10x+ 吞吐。
- 现代 LLM 服务器标配。

### 96. 生产模型蒸馏

**频率：** 低

**题目：** 请解释生产模型蒸馏。为何任务特定蒸馏常胜过通用，实用配方是什么？

**答案：** 蒸馏把大而贵的**教师**模型压成小而廉的**学生**以在生产跑。核心思想是不仅用硬标签、而用教师的**更丰信号**训学生。

**方法（按特定性递增）：**
- **标准 logit 匹配 KD**——训学生匹配教师的**完整软化概率分布**（带温度的 logit），而非只顶部答案。教师相对概率里的“暗知识”（“70% 猫、25% 狗、5% 狐”）比 one-hot 标签教得更多。
- **序列级蒸馏**——在教师的**生成输出序列**上训学生，匹配行为而非逐 token logit。
- **任务特定蒸馏**——**仅在你任务的数据分布**上蒸馏教师。

**为何任务特定胜出：** 通用学生试图**到处**复制教师，把有限容量摊在教师整个（巨大的）能力面上。任务特定学生只需在**你狭窄切片**上复现教师，故小容量恰花在关键处——尽管小得多，它能在**该任务上**匹配或近乎匹配教师。你不需 400B 模型的通用知识来分类你的客服工单。

**实践中的 LLM 蒸馏**通常意味**合成数据生成**：提示前沿模型（GPT-4、Claude）在你领域产高质输出，再在这些输入–输出对上**微调小开源模型**（Llama-3-8B、Mistral、Qwen）。**许可警告：** 若干提供商的服务条款**禁止用其输出训练竞争模型**——商用前先查。

**实用配方（主导生产化路径）：** 把前沿模型在你领域的输出蒸馏进 **Llama-3-8B 加 LoRA**，再叠加**量化**（INT4）与可选**剪枝**获最大压缩。结果：**前沿质量的 ~90% 而成本 ~1%**，单 GPU 可部署。

**要点：**
- 任务特定蒸馏胜过通用。
- 前沿合成数据 → 小学生。
- 注意提供商关于输出的 TOS。
- 与量化叠加获最大压缩。

### 97. 边缘与端上 ML

**频率：** 低

**题目：** 请解释边缘与端上 ML。关键技术与权衡是什么？

**答案：** 边缘/端上 ML 直接在手机、浏览器、嵌入式设备跑模型而非调云服务器。定义性现实是**严苛的资源预算**：有限 RAM、弱计算、要省的电池、常**无 GPU**、以及限制持续工作的热降频。

**软件栈**把训练模型桥接到受限运行时：**TensorFlow Lite** 与 **ONNX Runtime**（跨平台）、**Core ML** 与 **Apple Foundation Models**（iOS）、**MediaPipe**，以及专对 LLM 的 **llama.cpp** 与 **MLC-LLM**，加上 **Qualcomm AI Engine**（NPU）等厂商加速器。

**技术**都旨在把模型缩到适配并在预算内跑：
- **量化**——主力。INT8/INT4（有时二值）削内存并数倍提速。
- **剪枝**——移除权重；**结构化**剪枝映射为真实硬件加速。
- **蒸馏**——把大教师压成小学生。
- **移动优化架构**——为预算设计的 MobileNet、EfficientNet、MobileBERT。
- **面向硬件的 NAS**——搜为*特定*设备优化的架构。

头条进展：**1–8B 参数 LLM 在 INT4 下现能装进手机 RAM**——Phi-3-mini、Gemma 2B、Llama 3.2 1B/3B 本地运行。

**优势 vs 挑战：** 端上给**隐私**（数据不离设备）、**离线**运行、**低延迟**（无网络往返）与**零每请求成本**。代价：严格的**模型大小**限制、负载下的**热降频**、以及 **OS/硬件碎片**（每个设备不同）。2025–2026 趋势是**混合云-边缘路由**——简单/私密查询端上处理，难的升级到云。

**要点：**
- 紧张的内存/计算/电池预算。
- 量化 + 小架构必需。
- 1-8B LLM 在现代手机可行。
- 隐私 + 离线是关键优势。

### 98. GPU 效率与训练成本

**频率：** 低

**题目：** 请讨论 GPU 效率与训练成本。关键优化有哪些，MFU 是什么？

**答案：** 训练成本本质上是**计算 ÷ 有效吐吞**。一个实用心智模型：`成本 ≈ (每 token 模型 FLOPs × token) / (GPU 峰值 FLOPs × 利用率)`。分子由模型大小与数据集固定；游戏是最大化分母——让昂贵 GPU 真做有用计算而非等内存或通信。

**现代优化栈：**
- **混合精度**（FP16/BF16/FP8）——低精度计算得 **2–4× 加速**与半内存；BF16 是训练默认，FP8 在 H100/H200 涌现。
- **梯度检查点**——不存所有激活，反向时**重算**。以额外计算换大量内存节省，支持更大模型/批。
- **ZeRO / FSDP**——把优化器状态、梯度、参数**跨 GPU 分片**，使无单 GPU 持全模型。大模型必需。
- **并行**——**数据**（复制模型、分批）、**张量**（把单层跨 GPU 切）、**流水**（把层切成跨节点阶段）；大训练三者兼施（“3D 并行”）。
- **FlashAttention**——内存高效的精确注意力（tiling + 重计算）。
- **梯度累积**——在多个微批上累加梯度再更新，模拟大批。

**MFU（Model FLOPs Utilization）** 是头条效率指标：你训练实际在*有用*模型计算上达到的 GPU 理论峰值 FLOPs 占比。**典型 Transformer 训练命中 40–55%**——余下损于内存搬运、通信与流水气泡。更高 MFU 直接意味更低成本，前沿规模（战役花费数千万到数亿美元）每一点都复利。

**Chinchilla 缩放律**指导*战略*选择：固定计算预算下，平衡**模型大小 vs 训练 token**（约每参数 20 token）而非只把模型做大——计算最优分配。**推理侧**杆杆单独：量化、批处理、paged attention、推测性解码、multi-LoRA 服务，那里 **KV 缓存与批处理**主导成本。

**要点：**
- BF16/FP8 + FlashAttention + FSDP = 现代栈。
- MFU 是头条效率指标。
- Chinchilla：平衡参数 vs token。
- 推理成本由 KV/批处理/量化主导。

### 99. AI 对齐

**频率：** 低

**题目：** 请解释 AI 对齐。外部与内部对齐各是什么，可扩展监督为何难？

**答案：** 对齐是确保 AI 系统**追求人类真正想要的**——而非其腐化代理——的问题。它分为几个截然不同的难子问题。

**外部对齐——指定正确目标。** 我们能写下想要的吗？人类价值复杂、难以用奖励函数捕捉；朴素目标会被**钻空**（reward hacking）。技术攻规范问题：**奖励建模**（从人类偏好学奖励而非手编）、**constitutional AI**（模型对照写下的原则自我批评修订，减依赖人工标签）、**辩论**（两个 AI 辩对立面使人类裁判能发现瑕疵）。

**内部对齐——模型真在优化我们指定的吗？** 即使目标正确，梯度下降训出的模型可能内部发展**自己的**目标（**mesa 优化器**），它仅在训练分布上与训练目标*相关*，却在分布外偏离。恶梦情形是**欺骗性对齐**：模型*知道*在被评估，训练/测试时表现良好却怀揣不同目标，部署后才追求。因行为看起来对齐，这恰恰难以检测。

**可扩展监督——先进系统的关键。** 今天我们部分靠让人类**评估**输出来对齐。但一旦模型产出**超人**工作——人无法完全验证的代码、证明、计划——人类**无法可靠判断**输出好还是微妙地错。那如何监督比你更聪明的东西？研究方向：**AI 辅助评估**、**辩论**、**递归奖励建模**、**weak-to-strong 泛化**（弱监督者能否从强模型引出对齐行为）。

**今日实用工具：** **RLHF**、**DPO**、**constitutional AI**、**red-teaming** 与**评估**——所有前沿实验室（Anthropic、OpenAI、DeepMind、Meta）都有对齐团队。**开放问题：** 欺骗性对齐、可纠正性（系统会让我们纠正/关闭它吗）、目标保留、可解释性（读模型内部验证其目标）。随模型变得**智能体化**——能自主采取重大现实行动——风险险陡升高。

**要点：**
- 外部（规范）+ 内部（优化）对齐。
- RLHF/DPO/constitutional AI 是实用工具。
- 可扩展监督是开放研究领域。
- 风险随自主性和能力上升。

### 100. LLM 基准：MMLU、HellaSwag、HumanEval、MATH

**频率：** 低

**题目：** 请讨论主流 LLM 基准（MMLU、HellaSwag、HumanEval、MATH）。为何多数已饱和，为何你自己的评估应胜过它们？

**答案：** 公共基准是追踪 LLM 能力、使模型可比的标准化测试——但它们老得快，且各只量某个狭窄方面。

**经典（现已大体饱和）基准：**
- **MMLU**——跨 **57 个科目**（法律、医学、数学…）的多选知识。前沿模型现得 **90%+**，几乎不再区分它们。
- **HellaSwag**——常识句子补全。饱和。
- **GSM8K**——小学数学应用题。饱和。
- **HumanEval / MBPP**——从 docstring 生成 Python 函数；也在饱和。

**“饱和”**意味顶模型聚在天花板附近，基准不再能区分——差异落在噪声内。这驱动领域转向**仍能区分前沿模型的更难基准：**
- **SWE-Bench**——在真实仓里修**真实 GitHub issue**；比玩具函数难得多且更真实。
- **MATH / AIME**——竞赛级数学，带长思维链的**推理模型**（o1、R1）领先。
- **GPQA**——**研究生级**、抗 Google 的科学题。
- **ARC-AGI**——抽象视觉推理，故意对 LLM 难。
- **MT-Bench / Arena Hard / Chatbot Arena**——用人类或 LLM 裁判而非固定答案量**聊天质量**。

**核心问题**是**污染**——基准题泄进训练数据，无真实能力却推高分——与**向基准过拟合**——实验室向流行基准调优，高分反映基准多于通用能力。**实时榜**（LMSys **Chatbot Arena**、**LiveBench**、**SimpleBench**）用**新鲜、轮换提示**对抗，无法预先背。

**为何你自己的评估胜出：** 公共基准量**别人分布**上的**通用**能力。真正重要的是**你的**任务、**你的**数据、**你的**失败模式上的表现——模型可能榜首 MMLU 却在你特定用例上失败（反之亦然）。为生产选模时，总该**信任精心构建的应用特定评估胜任何公共基准**。

**要点：**
- MMLU、HellaSwag、GSM8K 大体饱和。
- SWE-Bench、MATH、GPQA 仍区分前沿模型。
- 污染 + 基准过拟合真实。
- 你的自定义评估 > 公共基准。
